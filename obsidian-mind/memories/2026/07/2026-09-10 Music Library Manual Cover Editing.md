# 2026-09-10: Ручная смена обложки для любых элементов Music Library

## Контекст и задача
Пользователь поставил задачу добавить возможность вручную изменять обложку/фотографию для любых элементов музыкальной библиотеки — как для исполнителей (`MusicArtist`), так и для альбомов (`MusicAlbum`) во всех разделах («Артисты», «Альбомы», «Сборники», «Коллекции») и внутри страницы деталей исполнителя (`ArtistDetail`).

---

## Реализованная архитектура и изменения

### 1. Бэкенд (`backend/routers/music_library.py`)
- **Мульти-разрешение сущностей (`_resolve_targets`)**:
  - Ранее функция `_resolve_target` возвращала либо только артиста, либо только альбом. В случае автономных альбомов (`standalone_album`) или карточек треков обе сущности делят один и тот же `folder_id`.
  - Новый метод `_resolve_targets(db: Session, folder_id: int) -> List[Union[MusicArtist, MusicAlbum]]` находит все сущности с данным `folder_id` и синхронизирует их состояние.
- **Инвалидация HTTP-кэша (`enriched_at = datetime.utcnow()`)**:
  - При вызове эндпоинта `POST /api/music-library/cover/{folder_id}` новое изображение сохраняется перманентно в `cache/music_covers/` через `img_cache.save_custom_image`.
  - Поле `target.custom_image_key` обновляется, старый неиспользуемый файл удаляется из кэша.
  - Поле `target.enriched_at` обновляется на текущее время UTC. Это гарантирует, что генерируемый фронтендом параметр `?v=<timestamp>` изменится, и браузер мгновенно обновит картинку без необходимости сброса кэша браузера.
- **Сброс к исходной обложке (`DELETE /api/music-library/cover/{folder_id}`)**:
  - Физически удаляет пользовательский файл из хранилища.
  - Очищает `target.custom_image_key = None`.
  - Обновляет `target.enriched_at = datetime.utcnow()`.

---

### 2. Модальный компонент выбора обложки (`frontend/src/components/CoverPicker.jsx`)
- **Универсальность**:
  - Принимает `{ folderId, title, currentUrl, hasCustomCover, onClose, onSaved }`.
  - Показывает текущую обложку в квадратном блоке предпросмотра (1:1).
  - Поддерживает два режима:
    1. `Файл`: выбор файла с диска или перетаскивание Drag & Drop с подсветкой дропзоны.
    2. `Ссылка`: ввод прямой ссылки на изображение в интернете с автоматическим отображением превью и атрибутом `referrerPolicy="no-referrer"`.
- **Управление и доступность**:
  - Закрытие по клавише `Escape` и клику вне модального окна.
  - Сохранение по нажатию `Enter` в поле ссылки.
  - Кнопка «Сбросить» (`Trash2`) отображается только если у карточки установлена кастомная обложка.
  - Индикация загрузки (`Loader2`) и блокировка кнопок во время отправки запроса.
  - Тосты об успешном сохранении/сбросе через `react-hot-toast`.
  - Визуальный стиль полностью интегрирован в общую дизайн-систему Zine / Dark (`#141210`, `#1c1916`, `#D4FF3F`).

### 3. Интеграция в интерфейс библиотеки (`frontend/src/components/MusicLibrary.jsx`)
- **Карточки артистов (`ArtistCard`)**:
  - Круглая кнопка с иконкой `ImagePlus` при наведении (в левом нижнем углу миниатюры).
  - Вызывает `onEditCover(artist.folder_id, artist.display_name, artist.custom_image_url || artist.image_url, !!artist.custom_image_url)`.
- **Карточки релизов в сетках (`AlbumOrItemCard`)**:
  - Кнопка с иконкой `ImagePlus` доступна во всех вкладках: «Альбомы», «Сборники», «Коллекции».
- **Страница деталей артиста (`ArtistDetail`)**:
  - Кнопка `ml-hero-edit` на аватаре артиста для быстрой смены его фотографии.
  - Проброс `onEditCover={onEditCover}` в сетку релизов артиста (`detail.albums`), благодаря чему обложка любого под-альбома или сингла редактируется прямо со страницы артиста.
- **Поддержка сенсорных экранов (`@media (hover: none)`)**:
  - На смартфонах и планшетах кнопки смены обложки и воспроизведения отображаются с постоянной прозрачностью `0.88`, что устраняет проблему отсутствия события `:hover`.

## 2026-09-20: Авто-enrich только для новых альбомов (new_only)

Причина: плановый проход каждые 15 мин (первый — через 5 мин после старта,
`backend/main.py:music_library_auto_enrich`) ретраил ВСЕ недообогащённые записи
(`_artist_needs_work`: `bio is None` или любой альбом без `cover_url`,
бэк-офф `RETRY_AFTER_HOURS=24`). Для андеграунда био/обложек нет в источниках —
проход 153 артистов повторялся при каждом старте, хотя файлы уже лежали в
`cache/music_images/` (дисковый кэш `music_image_cache` enrich вообще не проверяет —
он смотрит только поля БД `cover_url/bio/image_url`).

Изменение:
- `music_library_service._artist_has_new()` — отбор только ни разу не пробованных
  (`artist.enriched_at is None` или альбом с `enriched_at is None`, кроме «Треки»/дисков).
- `enrich_library(..., new_only)`, `_enrich_one_artist(..., new_only)`,
  `_enrich_albums(..., new_only)` — в new_only-режиме сеть только по новым записям;
  MB-поиск и био/фото для уже пробованных артистов пропускаются.
- `routers/music_library.run_scheduled_enrich()` теперь вызывает
  `enrich_library(force=False, new_only=True)` — старые неудачи дотягивает только
  ручной Rebuild `POST /api/music-library/enrich`.
- Попутно исправлено: фильтр `force=False` использовал константу `RETRY_AFTER_HOURS`
  вместо параметра `retry_stale_hours`.
- Тест `test_artist_has_new_only_never_attempted`, всего `49 passed`.
