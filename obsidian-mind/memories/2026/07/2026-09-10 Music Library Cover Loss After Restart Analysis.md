# Глубокий анализ проблем Music Library: Почему обложки пропадают после перезагрузки сервера

## 1. Введение и суть проблемы
Пользователь зафиксировал проблему: в модуле **Music Library** после перезапуска сервера (через `restart.bat`, остановку Docker или перезагрузку хоста) пропадают обложки альбомов и фото артистов, заменяясь генеративными цветными плашками с первой буквой («буква на градиенте»).

В ходе глубокого аудита базы данных PostgreSQL, бэкенд-сервисов, логов сервера, роутеров и фронтенда была установлена полная цепочка причин этого дефекта.

---

## 2. Состояние базы данных (PostgreSQL)
Была проведена непосредственная проверка живой базы данных:
- **Артисты**: 262 всего, из них 243 с заполненным `image_url` (93%), 262 обогащены (`enriched_at IS NOT NULL`).
- **Альбомы**: 3828 всего, из них 2681 с заполненным `cover_url` (70%), 3828 обогащены.
- **Удаление записей**: При старте сервера и вызове `sync_structure(db)` записи альбомов и артистов **НЕ удаляются** из БД (проверено тестовым прогоном с трекингом `db.deleted`, удалено 0 записей). Все 2681 URL обложек сохраняются в PostgreSQL.

---

## 3. Корневые причины исчезновения обложек

### Причина 1: Архитектурный дефект — обложки не скачиваются локально при обогащении
При выполнении Rebuild или фонового обогащения (`enrich_library` в `music_library_service.py`):
1. Сервис находит релиз в MusicBrainz и Cover Art Archive (CAA).
2. В базу данных сохраняется **только внешняя строка URL**:
   `https://coverartarchive.org/release/.../9914272220-500.jpg` или `https://upload.wikimedia.org/...`.
3. Сами бинарные файлы обложек **не скачиваются на диск и не сохраняются в VFS**.
4. Все обложки отдаются через динамический прокси-эндпоинт `/api/music-library/image?url=...`, который пытается скачать их на лету при первом открытии карточки в браузере.

### Причина 2: Сброс `_last_purge` и 48-часовой TTL кэша на диске
В `backend/services/music_image_cache.py`:
- Время жизни кэша обложек на диске ограничено 48 часами: `TTL_SEC = 48 * 3600`.
- Переменная `_last_purge = 0.0` объявлена на уровне модуля.
- При **каждом перезапуске сервера** процесс Python стартует заново, и `_last_purge` сбрасывается в `0.0`.
- Первый же запрос обложки в функции `purge_expired()` видит `time.time() - _last_purge > 3600` и **немедленно удаляет с диска все файлы `.bin` и `.meta`**, чей возраст превышает 48 часов (`mtime > 48h`).
- Если сервер работал пару дней или был выключен — при перезапуске весь диск-кэш обложек мгновенно стирается.

### Причина 3: Баг фронтенда — `v=Date.now()` ломает кэш браузера на каждый рендер
В `frontend/src/components/MusicLibrary.jsx`:
```javascript
function imgSrc(url, v) {
  if (!url) return url
  let src = url
  if (/^https?:\/\//i.test(url)) src = IMG_PROXY + encodeURIComponent(url)
  const stamp = v || Date.now()
  return src + (src.includes('?') ? '&' : '?') + 'v=' + encodeURIComponent(stamp)
}
```
Фронтенд пытается передать дату обогащения:
`src={imgSrc(artist.image_url, artist.enriched_at)}`
`src={imgSrc(img, item.enriched_at)}`

**Однако в `backend/schemas.py`**:
Поля `enriched_at` **НЕТ** ни в `MusicArtistCard`, ни в `MusicAlbumCard`, ни в `MusicArtistDetail`!
Следовательно:
- `artist.enriched_at` всегда равен `undefined`.
- `item.enriched_at` всегда равен `undefined`.
- На **каждый рендер компонента** выполняется `const stamp = Date.now()`.
- Браузер видит постоянно меняющийся URL с новым миллисекундным timestamp (`&v=1725975001234`).
- **Кэш браузера (HTTP Cache) полностью аннулирован**: браузер не может закэшировать ни одну обложку и при каждом переключении вкладок, поиске или обновлении страницы бомбардирует бэкенд десятками новых запросов.

### Причина 4: Синхронный `socket.getaddrinfo` в async-цикле и 502 Bad Gateway
Когда браузер открывает страницу и отправляет 30–60 одновременных запросов к `/api/music-library/image`:
1. Функция `_is_safe_host(url)` вызывает `socket.getaddrinfo(host, None)` **синхронно** прямо в event loop FastAPI, блокируя поток сервера на время DNS-резолвинга.
2. Сессии `aiohttp` обращаются к `coverartarchive.org`. Тот отвечает HTTP 307 Redirect на `ia800...archive.org`.
3. Серверы Internet Archive (`archive.org`) из РФ часто блокируются, замедляются провайдерами (РКН) или отвечают ошибками 429 Too Many Requests / 503 Service Unavailable / Timeout.
4. В `fetch_and_cache` при любой ошибке или таймауте (20 сек) возвращается `None`.
5. Роутер `/api/music-library/image` выбрасывает `HTTP 502 Bad Gateway (Image unavailable)`.

### Причина 5: Ловушка состояния `onError` в React (`ImgWithFallback`)
В `frontend/src/components/MusicLibrary.jsx`:
```javascript
function ImgWithFallback({ name, kind, src, className, style, alt }) {
  const [err, setErr] = useState(false)
  if (!src || err) return <Fallback name={name} kind={kind} />
  return <img src={src} ... onError={() => setErr(true)} />
}
```
Когда при старте сервера / холодном кэше запросы возвращают 502 или обрываются по таймауту:
- Тег `<img>` вызывает `onError`.
- Стейт `err` переключается в `true`.
- Компонент **навсегда** подменяет обложку на `<Fallback>` (букву на градиенте).
- Механизма автоматического повтора (retry) или восстановления нет: обложка «пропадает» для пользователя до ручного жесткого перезапуска страницы или повторного Rebuild.

### Причина 6: Перегрузка сервера фоновой авто-сборкой через 60 секунд после запуска
В `backend/main.py`:
Через 1 минуту после старта запускается `run_scheduled_enrich()`:
- Он вызывает `sync_structure(db)`, который выполняет **1572 тяжелых SQL-запроса** с джойнами по `folder_closures` и `vfiles` в течение 55 секунд.
- Затем запускается `enrich_library(force=False)`, который в цикле опрашивает MusicBrainz/CAA (в логах зафиксирована непрерывная работа в течение 45 минут с частыми таймаутами).
- Если пользователь открывает страницу в первые минуты после рестарта — сервер перегружен фоновыми запросами, и пользовательские запросы на выдачу картинок падают по таймауту.

## 4. Рекомендуемый комплекс решений

1. **Перманентное локальное хранение обложек (без TTL)**:
   - Обложки альбомов и фото артистов неизменны во времени. Они не должны иметь TTL 48 часов.
   - Скачанные обложки должны сохраняться бессрочно в `cache/music_images/` (или выделенной папке), а `purge_expired` не должен удалять валидные картинки.
2. **Исправление контракта схем Pydantic**:
   - Добавить поле `enriched_at: Optional[datetime] = None` в `MusicArtistCard`, `MusicAlbumCard` и `MusicArtistDetail` в `backend/schemas.py`.
   - В `imgSrc(url, v)` использовать строгий `v = item.enriched_at || '1'`, чтобы URL был статичным и браузер мог полноценно кэшировать картинки по HTTP.
3. **Асинхронный DNS и неблокирующий пул загрузки**:
   - Перевести резолвинг хостов в `_is_safe_host` на неблокирующий (`asyncio.to_thread(socket.getaddrinfo, ...)`).
   - Ограничить параллелизм обращений к внешним хостам через `asyncio.Semaphore`.
4. **Умный Retry во фронтенде (`ImgWithFallback`)**:
   - При ошибке `onError` делать до 2 попыток с экспоненциальной задержкой (1s, 3s) перед окончательным показом заглушки.
5. **Отложенный запуск фоновой авто-сборки**:
   - Увеличить `next_run_time` для `music_library_auto_enrich` в `main.py` с 1 минуты до 5–10 минут, чтобы дать серверу спокойно стартовать и обслужить пользователя.
