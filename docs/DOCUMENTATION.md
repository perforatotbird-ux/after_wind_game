## Обзор

Изометрический 3D-симулятор выживания: добыча ресурсов, переработка, фермерство, электрогенерация и восстановление разрушенного поселения после катаклизма. Текущее состояние — Глава 1 «Base Restored».

## Требования и запуск

- **Godot 4.7.2 stable** (целевая версия проекта).
- Python 3.9+ — только для тестового раннера.
- Blender не нужен: используются готовые GLB/TSCN, импорт `.blend` отключён (`filesystem/import/blender/enabled`).

```cmd
start.bat            :: игра (открывается стартовое меню)
start.bat --editor   :: редактор Godot
start.bat --test     :: все тесты headless
```

## Управление

| Клавиша | Действие |
|---|---|
| W, A, S, D | Движение относительно ракурса камеры |
| Пробел | Прыжок: можно двигаться в воздухе; повторный прыжок без приземления невозможен |
| Shift (удержание) | Спринт (тратит энергию; при перегрузе не ускоряет) |
| ЛКМ | Удар инструментом / взаимодействие с объектом в фокусе |
| ПКМ + мышь | Орбита камеры (чувствительность — в настройках) |
| Колесо мыши | Следующий / предыдущий инструмент пояса по кругу (рюкзак пропускается) |
| Ctrl + колесо | Зум камеры (3.5–26 м, шаг 1.5 м) |
| E | Действие: добыча, станки, урожай, NPC, подобрать предмет, забрать продукцию |
| 1–5 | Хотбар инструментов (5 — рюкзак, открывает инвентарь) |
| I / Tab | Окно рюкзака (клеточный инвентарь) |
| C | Выбор специализации (Шахтёр, Фермер, Учёный) |
| U / Y | Выпить воду / съесть еду |
| R / G / X (у делянки) | Сменить семена для посадки / зона работы 1×1 ↔ 3×3 / отменить неготовую делянку (дважды) |
| F5 / F9 | Быстрое сохранение / загрузка (слот автосохранения) |
| ESC | Меню паузы; в открытых окнах — закрыть окно |

Колесо не листает инструменты, пока открыто окно, игра на паузе или HUD блокирует ввод. Переназначение клавиш не поддерживается.

## Меню и настройки

Все окна собраны из общих стилей `scripts/ui/ui_style.gd` (те же цвета, рамки и кнопки, что у HUD).

**Масштаб и читаемость.** Интерфейс растягивается от базы 1600×900 (`project.godot`: `window/stretch/mode = canvas_items`, `aspect = expand`): на 1920×1080 он в 1.2 раза крупнее, на 1280×720 — в 0.8, раскладка везде одна. Поверх этого — настройка «Масштаб интерфейса» (75–150 %, `Window.content_scale_factor`).
- Окна HUD (заказы, ремонт, станция отправки, классы, пауза, финал) получают размеры из `hud.gd` (`WINDOW_SIZES`) и центрируются; если экран меньше, окно ужимается, а списки прокручиваются (`_layout_windows`, вызывается и при изменении размера окна).
- `UI.polish_text(окно)` вызывается после каждой перестройки содержимого: прокрутка только по вертикали, перенос строк у меток, «…» и подсказка у длинных названий в строках, шрифт не мельче 13 (кнопки — 14), оформление кнопок в стиле HUD.
- Требования заказов переносятся на новую строку (`HFlowContainer`), рецепты в окне станка — тоже.
- Хотбар, подсказка и уведомления подогнаны под ширину подписей (`_apply_hud_layout`).

**Стартовое меню** (`scripts/ui/main_menu.gd`). Открывается при запуске игры поверх живого мира: камера медленно облетает базу (оборот ≈ 2 мин), погода и сутки идут. Игрок, HUD и игровая камера на это время отключены.

| Пункт | Действие |
|---|---|
| ▶ Продолжить | Загрузить самое свежее корректное сохранение (по времени изменения файла). Неактивно, если сохранений нет; под кнопкой — слот, день, время и кредиты |
| ✦ Новая игра | Начать с чистого мира |
| 📂 Загрузить | Окно слотов (автосохранение + 3 ручных) |
| ⚙ Настройки | Окно настроек |
| ⏻ Выход | Закрыть игру |

Любой запуск партии перезагружает сцену мира: запрос передаётся через `GameSession` (meta у `SceneTree`) и разбирается в `world.gd` (`_init_session`), поэтому партия всегда стартует с чистого состояния. Меню показывается только если мир — текущая сцена и дисплей не headless (`@export enable_main_menu` позволяет выключить его); в тестах меню не появляется.

**Меню паузы** (ESC, `scripts/ui/pause_menu_controller.gd` поверх окна паузы HUD): продолжить, сохранить в слот, загрузить слот, настройки, громкость, чек-лист финала и «В главное меню».

**Окно слотов** (`scripts/ui/saves_panel.gd`): карточка на каждый слот — день, время, кредиты, дата записи; повреждённые файлы и файлы более новой версии помечаются ⚠️ и не загружаются. Перезапись и удаление слота требуют подтверждения (`scripts/ui/confirm_dialog.gd`). Сохранять в слот автосохранения вручную нельзя.

**Настройки** (`scripts/core/game_settings.gd`, окно `scripts/ui/settings_panel.gd`). Хранятся в `user://settings.cfg` (секция `[settings]`), применяются сразу и при каждом запуске. Значения из файла проверяются: вне диапазона — обрезаются, неверный тип — значение по умолчанию.

| Ключ | По умолчанию | Диапазон |
|---|---|---|
| `master_volume` | 1.0 | 0–1 |
| `sfx_volume` | 0.8 | 0–1 |
| `ambient_volume` | 0.6 | 0–1 |
| `fullscreen` | false | — |
| `resolution_index` | −1 (как в проекте) | −1…3: 1280×720, 1600×900, 1920×1080, 2560×1440 |
| `vsync` | true | — |
| `mouse_sensitivity` | 1.0 | 0.25–3.0 (множитель к 0.005) |
| `seconds_per_game_hour` | 60 (1 игровой час = 1 мин, сутки 24 мин) | 10–600 с; в окне — пресеты 20, 30, 45, 60, 90, 120, 180 с |
| `ui_scale` | 1.0 | 0.75–1.5; в окне — 75, 90, 100, 110, 125, 150 % |

Окно настроек разбито на разделы «Игра», «Звук», «Экран и интерфейс», «Камера» и прокручивается на маленьком экране. Длительность игрового часа применяется ко всем `DayNightCycle` (группа `day_night_cycle`, `set_seconds_per_game_hour`) сразу и при запуске. Она меняет смену дня и ночи и рост деревьев; станки, грядки, голод и жажда идут в реальном времени.

Кнопка «Сбросить» возвращает значения по умолчанию. Язык не настраивается (только русский).

## Время суток

`scripts/world/day_night_cycle.gd`. По умолчанию **1 игровой час = 1 минута** реального времени (сутки — 24 мин; раньше было 8 мин). Скорость настраивается (`seconds_per_game_hour`, см. [Меню и настройки](#меню-и-настройки)). Утро 5–11, день 11–17, вечер 17–21, ночь 21–5; сон в доме переносит на 6:00 следующего дня. `get_hours_per_second()` отдаёт текущую скорость другим системам (рост деревьев), `advance_hours()` продвигает время (переход отдыха).

**Отдых и сон** (`scripts/ui/rest_transition.gd`, `scripts/ui/sleep_dialog.gd`). Сон в отремонтированном доме (стадия 1+) открывает диалог с **ползунком длительности (1–12 ч)** и быстрыми кнопками; там же видно время пробуждения. По confirm запускается переход: затемнение, персонаж исчезает из мира, часы со стрелками с кольцом прогресса (~2.4 с) — игровое время идёт шагами синхронно с анимацией; повторный запуск заблокирован, движение и ввод выключены. Статы меняются в течение всего отдыха: энергия и здоровье к утру полностью; **метаболизм во сне замедлен (×0.35)**, поэтому сытость и жажда падают плавно (8 ч сна — примерно до 75 % и 66 %), а не в ноль с последующим подъёмом до 35 %. **Перемотка времени двигает все часовые процессы мира**: рост на делянках, фруктовых деревьях, кустах, грибах и саженцах, а также производство станков (циклы, топливо, продукция копится в станке). После сна — автосохранение и итог «💤 Вы отдыхали N ч».

## Сезоны и погода

Раздел 9 [мастер-плана](GAME_EXPANSION_MASTERPLAN.md). Реализован в двух частях: статический класс `scripts/core/seasons.gd` (календарь и множители — читают все, узел не нужен) и узел `SeasonManager` в `world.tscn` (`scripts/world/season_manager.gd` — ведёт календарь, запускает погодные события и применяет их последствия).

**Календарь.** 4 сезона × 7 игровых дней, год = 28 дней. Абсолютный игровой день однозначно определяет сезон, день в сезоне, день года и номер года (`Seasons.set_calendar(day)`); нужен только он — хранить календарь отдельно не надо. Новая игра начинается 1-го дня весны. Подпись в HUD: `🌱 Весна · день 3/7`.

| Сезон | Дни | Температура | Дожди | Рост | Испарение | Сбор ягод | Вода |
|---|---|---|---|---|---|---|---|
| 🌱 Весна | 1–7 | нейтрально (0 °C) | часто (0.45) | **×1.3** | ×1 | ×1 | живая |
| ☀️ Лето | 8–14 | +6 °C, база 24 °C | редко (0.15) | ×1 | **×2** | ×1 | живая |
| 🍂 Осень | 15–21 | −3 °C, база 9 °C | часто (0.40) | ×1 | ×1 | **×2** | живая |
| ❄️ Зима | 22–28 | −12 °C, база −6 °C | снег (0.50) | **×0.4** | ×0.4 | ×0.5 | **замерзает** |

Сезон задаёт четыре множителя (`Seasons.get_growth_multiplier()`, `get_evaporation_multiplier()`, `get_forage_multiplier()`, `get_rain_chance()`), температурное смещение для HUD и признак `water_freezes()`.

**Обратная совместимость.** Пока `Seasons.current_season == ""` (система выключена), все множители нейтральны (1.0), температурное смещение 0, `is_in_season()` пропускает любой список, вода не замерзает — то есть весь season-зависимый код работает круглый год. Этим пользуются тесты (`test_berry_bushes`, `test_farm_expansion`).

**Погода** (`scripts/world/weather_manager.gd`). Типов стало пять: солнечно, пасмурно, дождь, сильный ливень, **снег**. Цикл (`weather_change_interval`, по умолчанию 120 с) остаётся сезонным: зимой дождь превращается в снег (`_seasonal_weather`), а засуха выбрасывает из цикла дождевые состояния. Снег увлажняет почву вчетверо слабее дождя той же силы (`SNOW_HYDRATION = 0.25`) и **не** наполняет цистерны. Частицы: `RainParticles` и новый `SnowParticles` (медленное падение с турбулентностью).

**Погодные события** (SeasonManager, бросок в начале каждого игрового дня). У каждого — сезон, шанс в день, длительность в игровых часах и собственные множители:

| Событие | Сезон | Шанс/день | Длительность | Эффект |
|---|---|---|---|---|
| ⛈️ Гроза | весна, лето | 14 % | 2–6 ч | ливень; 35 % шанс, что молния сожжёт одно дерево (нужен саженец) |
| 🥵 Засуха | лето | 20 % | 3–5 дней | дождя не будет, испарение с грядок **×3** к сезонному |
| 🌨️ Метель | зима | 22 % | 4–12 ч | снег, урон от холода **×2**, скорость ×0.85, падает видимость |
| 🌀 Ураган | осень | 7 % | 2–4 ч | ливень, дом теряет 1 стадию, 15 % запасов разлетаются кучками |

Событие навязывает погоду (`get_forced_weather()`), запрещает дождь (засуха) и живёт по таймеру игровых часов — `get_hours_per_second()` берётся у `DayNightCycle`.

**Сезонные эффекты в игре.**
- *Фермерство* (`scripts/farming/farm_field.gd`): скорость роста умножается на сезонный множитель (весна ×1.3, зима ×0.4), испарение и расход воды — на сезонный множитель испарения (лето ×2, засуха ×3). Множители берутся у узла `SeasonManager` в группе `season_manager`, поэтому события видны и делянкам.
- *Ягоды и грибы* (`scripts/resources/berry_bush.gd`): сбор умножается на `Seasons.get_forage_multiplier()` — осенью ягод вдвое больше (`get_harvest_amount()`), зимой вдвое меньше.
- *Открытая вода* (`scripts/resources/resource_node.gd`, `freezes_in_winter`): зимой водоём промерзает — воду не набрать, поверхность белеет, подсказка и нажатие E объясняют, что нужен колодец. В `world.tscn` узел `WaterWell` переопределяет флаг в `false`: колодец работает круглый год.
- *Холод и жара* (`scripts/player/player.gd`, раздел 12.3 мастер-плана): `get_ambient_temperature()` складывает фазу суток, сезон и погоду; ниже `cold_threshold_temperature = 2 °C` на улице (без дома и печи) персонаж теряет здоровье, промокшая одежда усиливает холод (`1 + wetness/100`), метель удваивает урон. Летом с 12:00 до 17:00 жажда падает в 1.5 раза быстрее.
- *Вид* (`set_season_tint()` в `DayNightCycle`): небо, горизонт и свет солнца подкрашиваются поверх суточного расчёта — зима белее и холоднее, лето сочнее.

**HUD.** Под строкой погоды — строка сезона (`TopRightUI/…/SeasonLabel`): календарь плюс активное погодное событие с остатком времени (`⛈️ Гроза (ещё 3 ч)`). Температура в строке погоды считается как фаза + погода + сезон.

**Сохранение.** Новая необязательная секция `seasons` (`{enabled, total_day, current_season, day_in_season, year, active_event, event_hours_left}`) — см. [Сохранения](#сохранения). Версию формата не поднимает: старые сохранения без секции грузятся как есть, календарь восстанавливается по игровому дню.

Тест: `tests/test_seasons.gd`.

## Глава 2 «Первый дым»: кухня, грибы и восстановление станков

Раздел 2 [мастер-плана](GAME_EXPANSION_MASTERPLAN.md). Глава меняет стартовый баланс
базы: из четырёх станков **сразу работают только верстак и костёр**, а дробилка и
плавильня лежат завалами, а фильтр — разломанным очистителем на основе его исправной модели; их нужно восстановить.

### Новый стартовый баланс

| Станок | Состояние в новой игре | Стоимость восстановления | Что открывает |
|---|---|---|---|
| 🔨 Верстак | работает | — | компоненты, инструменты, кирпич |
| 🔥 Костёр | работает | — | базовая готовка с первого дня |
| ⚙️ Дробилка | **завалы** | 10 камня, 4 дерева, 50 кр. | камень → пыль, дерево → опилки |
| 🔥 Плавильня | **завалы** | 15 кирпичей, 6 камня, 2 глины, 80 кр. | обжиг, выплавка, выпечка |
| 💧 Фильтр воды | **разрушенный очиститель** | 8 песка, 4 дерева, 30 кр. | фильтрация воды |
| 🍳 Печь-кухня | **стройплощадка** | 8 кирпичей, 6 камня, 4 дерева, 90 кр. | средние блюда и соусы |

Механика — часть `ProductionMachine` (`requires_rebuild`, `rebuild_cost`,
`rebuild_credits`, `rebuild_info`, `rebuild()`). Пока станок не восстановлен, он не
берёт рецепты и не списывает сырьё; в мире вместо него стоят завалы
(`scenes/machines/machine_rubble.tscn`, узел `Ruined`; у фильтра — собственная разрушенная модель `assets/models/water_filter/water_filter_ruined.tscn`), а в окне станка — карточка
восстановления со списком того, что не хватает. Верстак и костёр
`requires_rebuild` не имеют и работают всегда. **Компоненты восстановления копятся внутри станка порциями**: кнопка «Внести компоненты» переносит из рюкзака всё, что есть (не больше нужного), и станок встаёт в ready, когда комплект собран — при прерывании ничего не теряется, прогресс виден в счётчике на кнопке.

| Топливо | Горение |

Рецепты (7, качество — обычное):

### Качество блюда и правило баланса

`CookingProgress.QUALITY_*` и `get_dish_quality()`: костёр даёт **обычное**, печь-кухня
Lv.1 — **хорошее**, Lv.2 — **отличное**. Качество блюда не ухудшается, если его
сварить снова на станке уровнем ниже.

Правило мастер-плана 7.1 проверяется тестом: **готовая еда всегда лучше сырых
ингредиентов** по сумме (сытость + жажда + энергия), а блюда печи-кухни — лучше
блюд костра на том же сырье. Это и есть смысл кухни: не «фармить», а готовить.

### Вехи главы

`scripts/crafting/cooking_progress.gd` (`CookingProgress`) — пять вех мастер-плана:

1. 🍲 Приготовить 5 разных блюд на костре
2. 🍄 Найти и собрать 10 грибов
3. ⚙️ Восстановить дробилку
4. 🔥 Восстановить плавильню
5. 🍳 Построить печь-кухню

Вехи видны в меню паузы под заголовком «Глава 2» вместе с отдельной строкой
прогресса. Блюда считаются по одному разу за вид (повторная готовка того же блюда
не закрывает новую веху, но наращивает счётчик), грибы — по факту сбора,
восстановления — по событию `machine_rebuilt`.

### Сохранение

Новые необязательные секции: `cooking` (`{dishes: {item_id: {count, quality}},
mushrooms_collected, rebuilt_machines}`), `mushrooms` (раскладка и состояние
грибов) и поле `machines[].rebuilt`. Версию формата не поднимают: старые
сохранения без этих полей грузятся как есть, станок без поля `rebuilt` считается
готовым. Битая секция отвергается целиком до изменения мира.

Тест: `tests/test_chapter2_smoke.gd`.

## Деревья и посадка

Срубленное дерево **само не отрастает** — остаётся пень (`scripts/resources/resource_node.gd`, `requires_planting`; включается автоматически для узлов группы `trees`). Камни и металлолом восстанавливаются как раньше (`respawn_time`). Глину и песок добывают только в жилах — см. [Жилы и копание](#жилы-и-копание).

1. При полной вырубке выпадает древесина и **🌱 саженец** (`sapling`, `sapling_yield = 1`). Урожай древесины: маленькое дерево (молодой дуб, сосна, раскидистая сосна) — 2 (8 ударов топором Lv.1 по 0.25), **большой дуб — 3** (бонус +1 за полную вырубку); 1.5 энергии за удар.
2. Подойдите к пню и нажмите E (топор не нужен): саженец списывается и сажается.
3. Саженец растёт `growth_hours = 8` игровых часов (8 мин при стандартной скорости). Модель плавно растёт от 18 % до 90 % размера, подсказка показывает процент и оставшиеся часы.
4. Выросшее дерево снова можно рубить.

В сохранении у ресурсного узла добавлены `is_growing` и `growth_hours` (необязательные; в старых сохранениях пни просто пустые).

## Фермерство: делянки

Делянка — фермерский участок любого прямоугольного размера от 1 до **128 клеток** (клетка 1 × 1 м), который игрок строит сам. Старые грядки базы (`farmland_plot.tscn`) остались как были.

**Как построить.**
1. Рюкзак (I / Tab) → кнопка **🌾 Делянка**. Рюкзак закрывается, включается размещение (`scripts/farming/farm_field_placer.gd`).
2. Наведите мышь на землю, **зажмите ЛКМ и тяните** — делянка растягивается по клеткам (больше 128 клеток не растянется), над ней размер и цена. Зелёная — место свободно, красная — занято: здания, станки, грядки, камни, стволы, жилы, вода, ягодные кусты, другая делянка или край карты. Отпустите ЛКМ — делянка размечена. ПКМ / Esc — отмена. Пока идёт размещение, удары и E выключены, ходить и крутить камеру можно.
3. На месте появляются колышки со шнуром, табличка и куча материалов. Подойдите и нажимайте **E** — из рюкзака забирается недостающее (можно приносить частями).
4. Когда всё принесено, стройка идёт **1 игровой день (24 ч)**: по мере прогресса появляются бортик и грядки. Пока делянка не готова, её можно отменить (**X** дважды) — материалы вернутся.

**Стоимость** (`FarmField.cost_for(w, h)`): древесина `4 + ⌈периметр / 2⌉` (бортик и колышки), камень `⌈клетки / 4⌉` (дренаж), опилки `⌈клетки / 4⌉` (мульча и компост). Например, 2×2 — 8 древесины, 1 камень, 1 опилки; 8×16 — 28 древесины, 32 камня, 32 опилок. Под делянкой убираются трава, цветы, мусор и декоративные кусты.

**Работа на делянке.** Подсвечивается клетка перед персонажем (или зона 3×3 — клавиша **G**). **E** выполняет нужное действие по порядку: убрать увядшее → собрать урожай → посадить → полить → удобрить; иначе подсказывает состояние. Каждая клетка засаживается своими семенами: **R** у делянки перебирает семена из рюкзака, в рюкзаке у семян есть кнопка «🌱 Сажать эти семена». Одна порция воды (`water` / `clean_water`) поливает клетку на +70 % или каждую клетку зоны 3×3 на +40 %. Одна порция удобрения — на 3 клетки. Дождь поливает все клетки.

| 🎃 Тыква | 30 ч | 40–80 % | 4 %/ч | через 10 ч | 1–2 | 1–3 | 22 | лето, осень |

\* Сезоны задают не только «растёт / не растёт», но и скорость: весна ×1.3, лето и осень ×1, зима ×0.4; летом и во время засухи вода испаряется быстрее (×2 и ×3). См. [Сезоны и погода](#сезоны-и-погода).

**Откуда берутся семена и саженцы.** Первые семена и саженцы привозит фермерша Марта — пока её самой в игре нет, посылки идут через Степана контрактами с наградой предметами (`reward_items` в `contract_db.gd`, на карточке заказа — «🎁»): «Посылка с семенами от Марты» (после 2 заказов: овощи и хлеб → семена подсолнуха, лука, фасоли, трав) и «Саженцы для фруктового сада» (после 4 заказов: зерно и вода → 3 саженца + семена капусты, томатов, перца, кукурузы, тыквы). Дальше хозяйство самодостаточно: верстак делает селекцию семян из урожая (`extract_*_seeds`, 15 с) и прививает саженцы из плодов (`craft_*_sapling`: плоды + древесина, 30 с).

**Старые грядки базы** (`farmland_plot.tscn`) выращивают только базовые три культуры (визуал стадий захардкожен): посадка других семян отклоняется с подсказкой про делянки. Всё новое — только на делянках. Посев на старой грядке учитывает **выбранные игроком семена** (R у делянки или кнопка «🌱 Сажать эти семена» в рюкзаке): выбраны семена картофеля — садится картофель, иначе — первые имеющиеся из базовой тройки.

**Механика роста** (по мотивам Stardew Valley, Farming Simulator и RimWorld):
- **Влага** 0–100 % у каждой клетки. В норме культура растёт с полной скоростью, суше нормы — ×0.4, переувлажнение — ×0.45…0.8 (у картофеля сильнее всех). Совсем сухая земля — рост стоит, копятся часы засухи; после предела культура **вянет** (E убирает). Пустая клетка сохнет на 1.5 %/ч. Цвет грядки показывает влагу: светлая — сухая, тёмная — мокрая.
- **Плодородие** 0–100 % (новая делянка — 60 %). Урожай истощает почву, удобрение даёт +35 % и ускоряет рост ×1.5 и +1 к урожаю, пустая клетка «под паром» восстанавливается на 0.5 %/ч. Почва ≥ 70 % — рост ×1.2, ниже 25 % — ×0.75 и −1 к урожаю.
- **Севооборот**: другая культура после прошлой на той же клетке — +1 к урожаю и вдвое меньше истощения; та же культура подряд истощает почву в 1.5 раза сильнее.
- **Качество** — доля часов роста в норме влаги: ≥ 60 % — «хороший» (+1), ≥ 85 % — «отличный» ★★ (+2).
- Фермер растит всё в 1.35 раза быстрее.

**Модель** (`scripts/farming/farm_field_meshes.gd`) собирается из частей, поэтому делянка любого размера выглядит одинаково аккуратно: приподнятые грядки с тремя бороздами, соломенная мульча-дорожка между ними, бортик из досок в два ряда с колышками через 2 м, табличка с размером, у стройки — колышки со шнуром и куча материалов. Культуры — по 4 стадии (посев, всходы, рост, зрелая) плюс увядшая; морковь — 2 ряда по 3 пучка с оранжевыми плечиками, картофель — 4 куста с цветами и клубнями, пшеница — 16 пучков колосьев. Грядки и растения — `MultiMesh`, поэтому даже 128 клеток почти ничего не стоят.

В сохранении — секция `farm_fields` (`[{x, z, w, h, state, delivered, build, cells: [[культура, рост, влага, плодородие, удобрено, увяло, засуха, уход, всего, прошлая культура], …]}]`).

## Фруктовый сад

Многолетние посадки из раздела 8.2 мастер-плана: саженцы сажаются на свободную землю, растут несколько игровых дней, затем плодоносят каждый сезон. Реализация: `scripts/resources/fruit_tree.gd` (дерево), `scripts/farming/fruit_tree_placer.gd` (размещение), контейнер `FruitTrees` в `world.tscn`.

| Дерево | Рост до урожая | Урожай | Сезон сбора |
|---|---|---|---|
| 🍎 Яблоня | 3 игровых дня (24 + 48 ч) | 4–8 яблок | осень |
| 🍐 Груша | 4 игровых дня (24 + 72 ч) | 3–6 груш | осень |
| 🍒 Вишня | 3 игровых дня (24 + 48 ч) | 6–12 вишен | лето |

**Как посадить.** В рюкзаке у саженца кнопка «🌱 Посадить в саду» → размещение мышкой (`GameplayUIController.start_placement("fruit_tree:<id>")`): ЛКМ — посадить, ПКМ / Esc — отмена. Проверки: не дальше 10 м и не ближе 1 м от персонажа, ≥ 2.5 м до других фруктовых деревьев, не на делянке и ягодном кусте, не на маске построек/скал/воды. Пока идёт размещение, удары и E выключены.

**Жизнь дерева.** Стадии `SAPLING → YOUNG → MATURE`, время роста идёт круглый год. Спелое дерево [E] собирает урожай в рюкзак (при полном — кучкой, через `give_or_drop`); плоды отрастают 24 ч, но только в свой сезон (без системы сезонов — круглый год). Пустое дерево с топором в руках [E] рубит: 8 ударов (1.5 энергии каждый), древесина по 0.25 (целая — каждая 4-я), при падении +2 древесины и возврат саженца. Спелое дерево с плодами собирается первым даже с топором — рубить его можно после сбора.

У груши визуал пока примитивный кодом (ствол-цилиндр, крона-сфера, плоды-шарики). Яблоня и вишня используют модели по референсам, см. [Модели яблони и абрикоса](#модели-яблони-и-абрикоса) и [Модель вишни](#модель-вишни). Масштаб по стадиям — 0.3 / 0.65 / 1.0.

В сохранении — секция `fruit_trees` (`[{type, pos, stage, growth, has_fruit, regrow, hits}]`); в старых сохранениях секции нет — сад пуст.

## Выживание

- **Энергия** — тратится на спринт, добычу и движение с перегрузом; восстанавливается отдыхом и сном в доме (стадия 1+). **Баланс сил и сытости**: в покое восстанавливается 0.5 %/с, при ходьбе — четверть, ночью на улице — половина, промокшим — ×0.7. Голод и жажда снижают восстановление, но не обнуляют его (ниже 20 % — ×0.25, ниже 40 % — ×0.5), поэтому постоянно перекусывать ради энергии не нужно. При 24+ ч без сна естественная регенерация выключается совсем — силы возвращают только сон и отдых.
- **Жажда** — падает со временем; вода из резервуара, фильтрованная или бутилированная вода (`U`).
- **Голод** — падает медленнее; овощи, картофель, хлеб, ягоды (`Y`). Ягоды здоровье не лечат.
- **Промокание** — под дождём (быстрее в ливень, `3.0 × intensity` %/с); высыхает постепенно: на улице ~0.12 %/с, в доме ~0.4 %/с, у плавильни ~2.0 %/с (в 3 раза быстрее, чем раньше — 0.35/1.2/6.0). Мокрая одёжа замедляет и отнимает силы.
- **Обморок и поражение** (`scripts/ui/collapse_transition.gd`): при 48 ч без сна или 0 здоровья персонаж падает. После вспышки splash (1.6 с) игрок либо просыпается у отремонтированного дома (стадия ≥ 2 — «Восстановленный дом») — время переходит на 08:00, статы частично восстанавливаются; либо появляется окно **Game Over** с кнопками «Продолжить» (быстрая загрузка) и «В меню». Штраф — 25 % ресурсов (кроме кредитов и инструментов) рассыпается кучкой у точки падения (`DroppedItem.spawn`). В headless‑тестах overlay пропускается и результат применяется мгновенно.
- **Истощение** — при нулевой энергии здоровье снижается (~0.5/с) с одноразовым предупреждением; при нуле также бьют жажда (1.2/с), голод (0.8/с) и бессонница 36+ ч (0.4/с). Здоровье восстанавливается само у сытого и напившегося персонажа и целиком за сон.

## Инвентарь и грузоподъёмность

Реализация: `scripts/inventory/inventory.gd` (модель), `scripts/ui/inventory_panel.gd` (окно), `scripts/ui/item_grid.gd` (сетка клеток), `scripts/ui/item_icons.gd` (иконки), `scripts/inventory/dropped_item.gd` (предметы на земле).

**Окно рюкзака** (I / Tab / слот 5). Пока окно открыто, персонаж не управляется (его обработка выключена); закрывается ESC, Tab или I.
- Сверху — шкала веса `текущий / допустимый кг` (цвет по состоянию нагрузки), занятые слоты, кредиты и инструменты пояса.
- Сетка 6 колонок, клеток столько, сколько `max_slots`. Каждая клетка — один стек: иконка ресурса и количество в углу (у стека больше 1 шт.); пустые клетки подписаны «Пустой слот».
- **Постоянные клетки** (`Inventory.slot_layout`, `get_slot_cells()`): у стека своё место. Добытое ложится в первую свободную клетку (или докладывается в свой стек), опустевшая клетка освобождается. Раскладка сохраняется в сейве (`inventory.slot_layout`, старые сейвы — раскладка по умолчанию).
- **Перетаскивание мышью**: стек в пустую клетку — перенос, на занятую — обмен (`move_slot`). Стек, брошенный за пределы окна, открывает «Выбросить…».
- **«⇅ Сортировать»** (`sort_slots`): по категории (ресурсы → материалы → продукция → компоненты → еда → семена), затем по названию; стеки одного предмета рядом.
- Двойной клик по еде / воде — съесть / выпить.
- Иконки рисуются кодом (`ItemIcons`, цвет и силуэт по категории/предмету) и кэшируются; у каждого предмета ItemDB есть иконка.
- Выбор клетки показывает карточку: название, описание, количество, вес штуки и вес всего стека. Для воды — кнопка «Выпить», для еды — «Съесть» (симулируют U / Y).
- **«🫳 Выбросить…»** или ПКМ по клетке открывает окно количества (`scripts/ui/quantity_dialog.gd`: ползунок + поле, кнопки «1», «½», «Всё»). Инструменты пояса выбросить нельзя.

**Предметы на земле** (`DroppedItem`). Выброшенное ложится перед персонажем кучкой с иконкой и подписью `×N`. Одинаковые предметы в радиусе 1.2 м складываются в одну кучку. E — подобрать: берётся сколько влезет в рюкзак, остаток остаётся лежать. Кучки сохраняются.

**Слоты (жёсткий лимит).**
- Рюкзак задаёт число слотов `max_slots` (по умолчанию 12; берётся из `slots` лучшего рюкзака на поясе).
- Стакаемый предмет занимает `ceil(количество / max_stack)` слотов. `max_stack` берётся из ItemDB, иначе 99; при `stackable = false` — 1 (слот на штуку).
- Раскладка по клеткам — `get_slot_stacks()`: полные стеки, затем остаток; сколько ещё влезет — `get_max_addable(item_id, amount)`.
- Инструменты и снаряжение (категории `tool`, `equipment`) висят на поясе и слотов не занимают.
- Если слотов не хватает, предмет не подбирается: `add_item` возвращает `false`, испускается `item_rejected(item_id, amount, "no_slots")`.

**Вес (мягкий лимит).** `max_weight = base_max_weight (рюкзак) + бонусы зданий`.

| Состояние | Условие | Эффект |
|---|---|---|
| NORMAL | вес ≤ max_weight | нет штрафов |
| OVERLOADED | вес > max_weight | ходьба ×0.6, спринт не быстрее ходьбы, +2.5 энергии/с при движении |
| CRITICAL | вес ≥ max_weight × 1.25 | персонаж обездвижен (скорость 0) |

Смена состояния — сигнал `load_state_changed` и уведомление игроку. Штраф применяется к `walk_speed`/`sprint_speed` родителя-игрока и снимается при возврате в NORMAL.

**Бонусы зданий** (`repairable_building.gd`, `set_weight_bonus`):

| Стадия | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Склад, кг | 0 | +10 | +20 | +35 |
| Дом, кг | 0 | 0 | 0 | +15 |

**Достройка порциями** (`repairable_building.gd`, `contribute()`). Материалы и кредиты следующей стадии **копятся внутри здания**: кнопка «Внести материалы» переносит из рюкзака всё, что есть (не больше нужного), в окне ремонта видно, сколько уже внесено; стадия применяется автоматически, когда комплект собран. Прерванную достройку можно продолжать с того же места (накопленное сохраняется в сейве: `house_delivered` / `storage_delivered`).

**Смена инструмента колесом** — `cycle_tool(direction)`: по кругу среди инструментов пояса, рюкзак пропускается.

## Производство и база

- **Дробилка** — камень в гравий/пыль, древесина в щепу. Модель — из Blender, с анимацией, см. [Модель дробилки](#модель-дробилки).
- **Верстак** — компоненты (рукояти, болты, ткань), инструменты Lv.2.
- **Плавильня** — кирпич, стекло, железные слитки (из металлолома или руды с углём). Модель — из Blender, см. [Модель плавильной печи](#модель-плавильной-печи).
- **Фильтр воды**, **станция сбыта**, **доска контрактов** (караванщик Степан).
- **Грядки** — вскопка, посадка, полив (ведро/дождь), удобрение, урожай.
- **Энергосеть** — ветрогенератор, батарея, фонари ночью.
- **Здания** — дом и склад, по 4 стадии. Дом — две модели по присланным референсам, см. [Модель дома](#модель-дома). Склад — две модели по новым референсам с отдельным инвентарём на 20 ячеек, см. [Модель склада](#модель-склада).

**Окно станка** (`scripts/ui/machine_panel.gd`, открывается по E у станка). Персонаж на это время не управляется; закрывается ESC или E.
- Основная область — **сетка рецептов** карточками одного размера (иконка продукции, название, вход → выход и время цикла; без сырья — серые, выбранный выделен). **Рюкзак игрока — справа**, нужное сырьё подсвечено. Внизу — состояние станка, топливо (у печи) и готовая продукция.
- **Сколько произвести** — поле с шагом, равным выходу одного цикла (принимаются только кратные значения, например 10 каменной пыли = 10 циклов дробления). Максимум — сколько позволяет сырьё в рюкзаке (не больше 99 циклов). Ниже — сколько сырья спишется и сколько займёт времени.
- **▶ Старт** — сырьё на всю партию сразу списывается из рюкзака (`start_batch`), циклы идут подряд. Видны прогресс цикла, номер цикла и оставшееся время.
- **⏹ Отменить** (с подтверждением) — партия останавливается, **сырьё не возвращается**, уже готовая продукция остаётся.
- Внизу — сетка рюкзака (ресурсы, нужные рецепту, подсвечены) и сетка выхода станка. Вся готовая продукция станка (как одиночные циклы `start_recipe`, так и партии `start_batch`) накапливается в собственном инвентаре станка (`pending_outputs`). При открытии станка [E] продукция остаётся в станке; игрок может забрать её целиком («📦 Забрать всё») или кликом по конкретной ячейке выхода (`collect_output_item`).

**Электропитание.** Станки — потребители энергосети (`power_draw`, кВт: дробилка 3.0, верстак 1.0, плавильня 5.0, фильтр 1.2): мощность списывается, только пока станок реально работает. Если батарея пуста, сеть обесточивает станки — цикл замирает на паузе (сырьё и прогресс партии не теряются), при восстановлении питания производство продолжается, анимация станков (маховики дробилки) останавливается вместе с циклом. Чтобы станки не «мигали» на пустой батарее, сеть возвращает питание при положительном балансе или заряде ≥ 15 %. Батарея заряжается с КПД 1/3 — базовый ветряк наполняет её втрое медленнее, чем раньше.

**Источник питания** — рубильник на батарее ([E] у Батарейного накопителя, циклически): **Сеть** (авто — ветряк питает базу, излишек заряжает батарею, батарея покрывает пики и ночи), **Ветряк** (потребители только на генерации — слабее, станки встают, если ветра не хватает; батарея не тратится и копит излишек), **Батарея** (вся нагрузка на батарее — тратит ёмкость, ветряк подзаряжает её с КПД). Выбор виден в HUD рядом с процентом сети и в подсказке батареи; режим сохраняется в сейве (поле `source_mode` секции `energy`). Если сеть обесточена, HUD объясняет причину: «Батарея разряжена», «Потребление X кВт > генерация Y» или «Нет мощности».

**Сохранение и загрузка.** При загрузке `save_manager.gd` для каждой машины вызывает `set_process(running)` прямо в секции загрузки машин — `_ready()` выключает `process` для всех станков, поэтому без этого они зависли бы на месте даже при наличии питания. Также при загрузке восстанавливается `power_ok` из `PowerGrid.has_power` и сбрасывается `_last_emitted_progress`, чтобы партия не «прыгнула» в начало. Статический прогресс контрактов (`ContractDB.completed_contracts`) сбрасывается при новой игре (`slot_id == `) и при загрузке, если в сейве есть секция `contracts` — иначе старый сейв без контрактов унаследовал бы прогресс другой сессии.

**Износ и ремонт** (`scripts/crafting/machine_wear.gd`, общий компонент). Станок изнашивается за каждый завершённый цикл (0.5 состояния из 100); ниже 50 % — «изношена», циклы ×1.25 дольше; при 0 — «неисправна»: новые запуски блокируются. Ремонт — кнопка в окне станка: 2 болта + 1 деревянная рукоять дают +50 % состояния. **Детали ремонта/улучшения копятся внутри станка порциями**: кнопка переносит из рюкзака всё, что есть (не больше нужного), а работа выполняется, когда комплект собран — достройку можно вести за несколько подходов, ничего не теряется. Состояние видно в окне станка и сохраняется.

**Уровни машин** (`scripts/crafting/machine_level.gd`, общий компонент). Станки улучшаются на месте кнопкой в окне: Lv.1 «Базовая» → Lv.2 «Улучшенная» → Lv.3 «Передовая». Эффекты уровня: циклы быстрее (×0.75, далее ×0.6), износ за цикл меньше (0.3, далее 0.2 при базовых 0.5), ресурс станка больше (120, далее 150), потребление сети выше (×1.3, далее ×1.6), сила персонажа за цикл ниже (×0.8, далее ×0.65), КПД топлива печи выше (×1.3, далее ×1.6). Спецбонусы: дробилка добавляет +1 к выходу каждой позиции за уровень (2 камня → 2 пыли на Lv.2), фильтр +2 (2 воды → 4 чистой), улучшенный верстак и печь получают рецепты компонентов Lv.2. Улучшать можно только свободный станок; детали **переносятся в станок порциями** (кнопка «Внести детали» со счётчиком внесённого), уровень растёт, когда комплект собран; состояние износа пересчитывается пропорционально новому ресурсу. Стоимость (детали делают сами станки — порядок улучшений возникает сам): дробилка — 6 камня, 4 пластины, 2 шестерни, 4 болта; верстак — 2 рукояти, 4 пластины, 2 шестерни, 4 болта; плавильня — 6 обожжённых кирпичей, 6 пластин, 2 шестерни, 4 болта; фильтр — 4 песка, 2 пластины, 1 шестерня, 2 болта. Lv.3 требует сталь и точные шестерни с улучшенного верстака. Уровень сохраняется в сейве (поле `level`).

**Компоненты Lv.2** (рецепты с `min_level: 2`, доступны только на улучшенных станках): верстак — **Стальная пластина** (2 пластины + уголь → 1, 40 с) и **Точная шестерня** (2 шестерни + пластина → 1, 50 с); печь — **Стальной слиток** (2 слитка → 1, 90 с, топливо из слотов); фильтр — **Целебная вода** (2 чистой + стекло → 1, 35 с; пьётся ради здоровья +15 даже при полной жажде). Стальные детали дают **качественный ремонт** машин: 2 болта + стальная пластина восстанавливают +70 % состояния вместо +50 %.

**Топливо печи.** У плавильни — 4 независимых топливных слота (до 9 штук в слоте): уголь горит 240 с, дрова — слабое аварийное топливо, всего 10 с, топливный брикет 360 с. Топливо кладётся из рюкзака (клик по пустому слоту или «⛽ Заправить»), клик по заполненному слоту забирает его назад. Печь расходует горение по времени; запуск партии требует запаса горения на все циклы (иначе отказ до списания сырья), а если топливо кончилось посреди партии — цикл встаёт на паузу до заправки. Топливо больше не является ингредиентом рецептов печи.

Станок считает завершённые циклы (`completed_runs`).

### Модель и анимации костра

Модель создана в Blender по предоставленному `campfire_multi.jpg`: неровное кольцо из 14 камней, земля/зола, шесть поленьев шалашом и три поперечных полена, древесная фактура и кольца на торцах, 18 щепок, мелкие камни и 28 угольков. **16 892 треугольника**, пять статичных мешей (семь поверхностей) вместо десятков отдельных объектов; игровые текстуры и меши — компактные `.tres`. Сцена — `assets/models/campfire/campfire_model.tscn`, подключена в `scenes/machines/campfire.tscn`; котелок и прежние примитивы удалены, у очага есть твёрдая коллизия.

`campfire_visual.gd` добавляет восемь изогнутых языков пламени с шейдерным изгибом/мерцанием, жёлтой сердцевиной и оранжевыми краями, искры и мягкий дым с альфа-текстурой, свет с пульсацией, светящиеся трещины в углях и постепенное обугливание поленьев. Есть состояния: свежие дрова → разгорание → горение → угасание/тление → холодные обугленные поленья. При окончании топлива пламя гаснет примерно за 0.4 с, угли остывают около 3 с, дым ненадолго остаётся; постоянного света и новых искр без топлива нет.

**Фактическое горение:** `Campfire._process()` теперь расходует топливо всегда, а не только во время готовки. Подкладывание дров, угля или брикетов разжигает костёр сразу; очередная единица подхватывается без мигания, даже при большом `delta`. Во время рецепта секунды горения и прогресс готовки учитываются один раз. После готовки или отмены партии оставшееся топливо продолжает догорать. Из слота возвращается только ещё не зажжённый запас — активное полено не возвращается в рюкзак и не тушится от изъятия запаса. Длительности **15/90/120 с** и рецепты не изменены.

Сейв сохраняет остаток горения и запас топлива прежними полями, а обугливание — необязательным `fire_has_burned` только у костра. При загрузке визуальное состояние и независимое горение восстанавливаются сразу; старые сейвы без поля поддерживаются. `player.is_near_heat()` исключает негорящий костёр, не меняя остальные источники тепла.

Повторная сборка (bpy 5.1.2):

```bash
python tools/create_campfire_model.py campfire_build --render
godot --headless --path . -s tools/import_campfire_model.gd -- campfire_build
```

Blender и промежуточные GLTF/PNG для запуска не нужны. `test_campfire_model.gd` проверяет модель и эффекты, расход без готовки, смену поленьев, отсутствие двойного списания, завершение/отмену рецепта, возврат запасного топлива, тепло, угасание ночью и сохранение горящего/потушенного состояния, совместимость старых и отказ некорректных сейвов.

**Архитектура:** деревянный амбар с вертикальной дощатой обшивкой, массивными стойками и подкосами, железными накладками и заклёпками, каменным цоколем, двускатной деревянной кровлей с рифлёными металлическими заплатами. Две открытые створки ворот с железными ремнями и ручками; за входом — настоящие стеллажи, ящики и бочки. Над воротами — блок с канатом и крюком, по бокам — подвесные фонари.

| Стадия | Что видно | Хранилище | Прежний бонус к весу рюкзака |
|---|---|---|---|
| 0 Разрушенный склад | сквозные проломы кровли и стен, повреждённые ворота, сломанные стропила, доски и камни перед входом | недоступно | 0 кг |
| 1 Расчищенный навес | очищенный каменный цоколь, пол и укреплённый каркас с тентом | недоступно | +10 кг |
| 2 Крытый амбар | восстановленная модель, чистый двор, целая кровля, заполненные стеллажи, фонари | **20 ячеек** | +20 кг |
| 3 Логистический комплекс | тот же амбар, работающий фасадный подъёмник | **20 ячеек** | +35 кг |

- Фасад — +Z, во двор; склад остаётся на прежнем месте базы. Основной объём ≈ 4.4 × 3.55 м, кровля ≈ 5.24 × 4.2 м, высота ≈ 4.5 м. Коллизия основного здания подогнана под новый объём; вход в интерьер не требуется — взаимодействие снаружи у ворот.
- Около 44 тыс. треугольников на модель, архитектурные части объединены, движущиеся детали имеют локальные оси. Меши — сжатые `ArrayMesh` в текстовых `.tres`, каждый ресурс <1 МиБ. Собственные материалы дерева/камня и нормали 1024² разделяются с домом (`assets/models/house/`); вариации досок и камней — в цветах вершин. Исходные референсы и Blender для запуска игры не нужны.
- Фонари восстановленного склада светят ночью по `DayNightCycle`, днём дополнительные источники выключены. В разрушенном состоянии они пустые и не светят.
- Подъёмник финальной стадии сохраняет прежний 12-секундный цикл и высоту 0.45 м: вращение блока и рукоятки, сокращение каната, подъём и покачивание небольшого ящика, спуск. Реализация — `storage_hoist_animator.gd`, узел `Visuals/Stage3/HoistAnimator`; координаты перенесены к фасаду нового амбара.

**Отдельный инвентарь склада** (`product_storage.gd`, `warehouse_inventory.gd`, `storage_panel.gd`):
- Доступен со стадии **2** (готовый крытый амбар), вместимость **ровно 20 ячеек** на стадиях 2 и 3. Размер стека — из `ItemDB`, как в рюкзаке. Инструменты и снаряжение пояса не переносятся; ресурсы, материалы, продукция, семена и еда — переносятся.
- E у готового склада открывает две сетки: личный рюкзак слева, склад 5 × 4 справа. ЛКМ — окно количества (1 / половина / все), ПКМ — перенос выбранного стека. Перетаскивание внутри складской сетки меняет местами ячейки. ESC / TAB / I закрывают окно.
- Пока окно открыто, движение и игровой ввод заблокированы. «Ремонт / улучшение» открывает прежнее окно стадий; оттуда кнопка «Открыть склад (20 ячеек)» возвращает к предметам. На разрушенном складе E по-прежнему открывает ремонт.
- Перенос учитывает свободные ячейки и остатки стеков назначения. При нехватке места переносится только помещающаяся часть; остаток не теряется и остаётся в источнике. Складские предметы **не входят в вес рюкзака**; прежние бонусы +10/+20/+35 кг не отменены.
- При понижении стадии ниже 2 предметы **сохраняются**, но доступ к ним закрыт до восстановления. Ящики модели — декор, не бесплатный источник предметов: новый инвентарь пуст.
- Содержимое и порядок ячеек сохраняются в необязательном поле `buildings.storage_inventory = {items, slot_layout}`. Старые сейвы создают пустое хранилище. Некорректные количества, неизвестные предметы, >20 стеков или ячеек отклоняются **до изменения мира**. Формат сейва остаётся v2.

Стоимость восстановления и прежние бонусы зданий не менялись; добавлены собственное хранилище и новый визуал.

**Пересборка** (Python с `bpy` 5.x, numpy и Pillow):
```bash

godot --headless --path . -s tools/import_warehouse_models.gd -- /tmp/warehouse_build
```
Конструктор использует общие процедурные текстуры/геометрические помощники `create_house_models.py`, но строит собственную архитектуру амбара. Тесты: `test_storage_model.gd` (модели, стадии, свет, подъёмник и бюджет) и `test_storage_inventory.gd` (20 ячеек, переносы, заполнение, вес, сохранения/старые и повреждённые сейвы, ремонт и UI).

### Модель дома

`scenes/buildings/repairable_house.tscn` теперь использует две собственные модели по присланным `House_wreck.jpg` и `House.jpg`, вместо прежних примитивов. Ресурсы — `assets/models/house/`, визуальные состояния и эффекты — `scripts/buildings/house_visual.gd`.

Дом остаётся в `(-6.2, 0, -5.5)`. Основной объём около 4.9 × 3.8 м, кровля около 5.9 × 4.7 м, высота около 5.1 м. ## Жилы и копание

Реализация: `scripts/world/voxel_deposit.gd` (жила), `scripts/world/voxel_textures.gd` (текстуры), `scripts/world/ground_terrain.gd` (вырез в земле), шаг на уступ — `player.gd` (`_try_step_up`).

**Как играется.** Жила — участок земли 8×8 м из разрушаемых блоков 0.5 м глубиной 4 м (16×16×8 блоков). Сверху это обычная трава; выдают её только камешки-«выходы» породы (рыжие — руда, чёрные — уголь, светлые — песок/глина). Наведите курсор на блок рядом с персонажем (досягаемость 3.0 м от груди — хватает на второй слой сверху; без мыши — блок перед персонажем: стенка, затем грунт перед ногами, затем под ногами) и бейте ЛКМ или E. Мотыга разрушает то место, куда попало лезвие (точка курсора в момент удара, `aim_at_cursor`); квадратной подсветки блока нет — прицелом служит сам курсор, а подсказка называет блок, инструмент и прочность. Копаются строго блоки под курсором (соседние «по взгляду» мотыга не трогает); персонаж доворачивается к курсору даже через спину.

| Блок | Инструмент | Ударов (Lv.1) | Добыча | Энергия за удар |
|---|---|---|---|---|
| Грунт | мотыга (кирка +1 удар) | 1 | земля ×1 | 1.2 |
| Песок | мотыга (кирка +1 удар) | 2 | песок ×2 | 1.4 |
| Глина | мотыга (кирка +1 удар) | 2 | глина ×2 | 1.8 |
| Уголь | только кирка | 13 | уголь ×3 (13×0.25) | 1.4 |
| Железная руда | только кирка | 4 | руда ×1 | 2.0 |
| Скальное основание, внешние стенки | — | не копаются | — | — |

- Инструмент Lv.2: двойной удар, −35% энергии, +1 к добыче ресурса. Шахтёр: +1 угля/руды и −20% энергии на них.
- Дробная добыча: камень/дерево/уголь/руда идут по 0.25 за удар и копятся в узле/блоке (`_yield_pool` / `yield_pool`); целые штуки выдаются по мере накопления, остаток < 1 сгорает при истощении. Итоги Lv.1 без классовых бонусов: валун — 4 камня (10×0.25+2), дерево — 2 древесины, блок угля — 3, ведро — 2 воды за забор (бонус за истощение убран). Новый предмет `soil` (Земля ×1 с блока грунта, пока ни во что не перерабатывается).
- Ресурсы лежат пятнами по глубине (слой 0 — трава): песок 1–3, глина 1–5, уголь 2–6, руда 3–6; нижний слой — скальное основание. В жиле 1–3 вида ресурсов (`resource_types` или случайно по `deposit_seed`). Первый выкопанный блок ресурса — сообщение «Найдена жила», найденное видно в подсказке.
- Если рюкзак полон, добыча падает кучкой у блока. Кучки подбираются клавишей E; удар ЛКМ их игнорирует и бьёт инструментом.
- Выбраться из ямы: персонаж сам шагает на уступ в 1 блок (`STEP_HEIGHT = 0.55`, только тела группы `voxel_terrain`), уступ в 2 блока — уже стена. Копайте ступенями.
- Жилы не восстанавливаются: выкопанное остаётся ямой (и в сохранении).
- На карте 3 жилы (`Deposits` в `world.tscn`): «Ближняя» (8, 15) — песок и глина, «Восточная» (18, −6) — уголь и руда, «Западная» (−18, −2) — случайный набор (сид 37).

**Новые предметы и рецепты.** `coal` (уголь), `iron_ore` (железная руда). Плавильня: `smelt_iron_ore` — 2 руды → 1 железный слиток (уголь кладётся в топливный слот печи). Верстак: `press_coal_briquette` — 2 угля + 1 опилки → 3 топливных брикета; уголь также идёт в аккумуляторный элемент. Время циклов — в разделе [Баланс](#баланс-и-прогрессия-главы-1).

**Техника.**
- Воксели — `PackedByteArray` (`x + z·N + y·N²`), материалы `Mat`: AIR, SOIL, SAND, CLAY, COAL, IRON_ORE, BEDROCK. После каждого разрушенного блока меш (только открытые грани, атлас UV, затемнение по глубине) и `ConcavePolygonShape3D` пересобираются целиком — для 2048 блоков это миллисекунды.
- Персонаж каждый кадр вызывает у жилы `update_aim(player)`; расстояние, поворот и проверка удара берут `get_interaction_point()` / `is_in_reach()` (общие методы для объектов с прицелом). Свойства `required_tool` и `current_hits` относятся к блоку под прицелом, поэтому замах и hit-stop работают как у камней. Удар мотыгой всегда идёт строго в блок под курсором мыши (`aim_at_cursor`, без fallback на направление взгляда).
- Темп удара киркой — как удар топором по дереву (`player._pickaxe_timing`): длительность замаха берётся от клипа `chop`, а момент контакта — в той же фазе своего клипа `mine`, поэтому вспышка повреждения синхронна с приземлением головки.
- Текстуры — процедурные пиксельные тайлы 32×32 (трава, дёрн сбоку, грунт, песок, глина, уголь, руда, скальное основание) в атласе с рамкой 8 px против смешивания mipmap-ов. Земля мира — гладкий моховой шейдер без пикселей, см. [Луг и декор](#луг-и-декор). Превью: `godot --headless --path . -s tools/export_voxel_textures.gd -- out.png`.
- `ground_terrain.gd` заменяет ящик земли 80×80 полосами вокруг участков жил (`get_footprint_rect`); на участке землю держит и рисует сама жила.
- Новая жила: узел `Area3D` со скриптом `voxel_deposit.gd` в `Deposits`, верх участка на y = 0, без поворота, на свободном месте (камни и постройки внутри участка будут висеть над ямой).

## Луг и декор

Реализация: `scripts/world/meadow_ground.gd` (шейдер земли), `scripts/world/meadow_grass.gd` (меши и шейдеры травы), `scripts/world/meadow_decor.gd` (узел `Meadow` в `world.tscn`). Тесты — `tests/test_meadow_and_debris.gd`, `tests/test_stylized_grass.gd`.

- **Глина и песок больше не лежат шарами на карте** — узлы `Clay1/2`, `Sand1/2` и плоский квадрат двора `DirtYard` удалены. Глину и песок дают только жилы: в «Ближней» и «Западной» вместе ≈ 100 блоков песка и ≈ 90 блоков глины, по 2 единицы с блока — с большим запасом на всю Главу 1 (нужно ~24 глины и ~3 песка). Сцены `clay_node.tscn`/`sand_node.tscn` остались в проекте, но не используются.
- **Земля** (`MeadowGround.get_material(yard_rect)`, `ShaderMaterial`): гладкий тёмно-зелёный «мох» (смесь двух оттенков по fbm-шуму) под травой, сочные и выгоревшие пятна, редкие проплешины голой земли с крапинками. Вокруг базы — вытоптанный двор с неровным краем (`yard_rect` у `Ground`, по умолчанию `Rect2(-11, -9, 22, 16)`; `yard_signed_distance` < 0 — внутри).
- **Декор** генерируется при старте детерминированно (`decor_seed = 4242`, у каждого слоя своё зерно, ~400 мс):

| Слой | Сколько | Как сделано |
|---|---|---|
| Пучки травы | ≈ 40 000 (~7 на м²) | стилизованные пучки `MeadowGrass`, `MultiMesh` по чанкам 12 м × вид × вариант; вблизи (до 36 м) — полные пучки, дальше — простой дальний пучок на каждый третий |
| Клевер | ≈ 5 800 | трилистники пятнами у корней травы |
| Цветы | 900 | группами, 5 цветов (белые, жёлтые, синие, фиолетовые, розовые) |
| Кусты | 46 | `StaticBody3D` группы `bushes` с коллизией-цилиндром; 6 вариантов (с ягодами и цветами), чаще на опушках |
| Камешки, ветки, листья, грибы | 380 / 170 / 650 / 70 | листья и грибы — под деревьями |
| Обломки после бури | доски 50, кирпичи 45, листы металла 22 | в основном вокруг двора |

- **Стилизованная трава** (`meadow_grass.gd`) — как на референсе: толстые изогнутые листья со скруглёнными кончиками, тёмные у корня и жёлто-зелёные на концах.
  - Виды пучков: `LUSH` (сочный, 3 варианта), `LUSH_WIDE` (широкие листья), `TALL` (дикие высокие куртины по шуму), `SHORT` (примятая у края двора), `FAR` (дальний план), `CLOVER`. Пучок — 70–100 треугольников, меши кэшируются.
  - Шейдер: двусторонние листья, мягкий свет (`lambert_wrap`), просвечивание (`BACKLIGHT`), затенение у корня, ветер с порывами, нормали частично смотрят вверх — луг не «рябит». Цвет пучка подкрашивается по шуму: сочные и выгоревшие (желтоватые) пятна.
  - Трава растёт и на жилах; когда блок верхнего слоя выкопан, пучки над ним прячутся (жила шлёт сигнал `terrain_rebuilt`, луг вызывает `sync_with_deposits()`, счётчик `counts["grass_hidden"]`). Работает и после загрузки сохранения.
- Декор не залезает на станки, здания, грядки, декоративные скалы, ресурсы и жилы: строится маска 0.25 м (`get_mask_at`) по их мешам (`node_footprint`, без высоких деталей вроде лопастей ветряка) и стволам деревьев. Трава и мусор — без коллизии и без теней (кроме кустов).
- Чтобы поменять плотность — экспорты `grass_step` (шаг сетки травы, 0.36 м), `grass_lod_distance` (36 м), `flower_count`, `bush_count` и др. у узла `Meadow`; `generate()` пересобирает всё.

## Модель Странствующего торговца

Степан (`scenes/npc/trader_npc.tscn`) использует присланную модель `торговец.glb` вместо старых примитивов. Игровая сцена — `assets/models/trader/wandering_trader.tscn`: рост 1.8 м, 26 000 треугольников вместо 499 656, 17 костей, четыре части одного skinned-меша; общий PBR-материал, цвет 1024, нормали и ORM 512. Исходный файл без скелета и анимаций не нужен для запуска игры.

- **Ожидание (`idle`, 4 с)** — дыхание грудью, лёгкие движения головы и рук; ноги стоят на земле, старое подпрыгивание всей модели удалено.
- **Приветствие (`greet`, 2.4 с)** — жест рукой и кивок при нажатии E; затем автоматически начинается разговор.
- **Разговор (`talk`, 3.2 с)** — кивки и жесты; повторяется, пока открыто окно контрактов. Модель плавно поворачивается к игроку, а после закрытия окна возвращается к ожиданию и исходному направлению. Открытие доски контрактов также завершает разговор.
- **Ходьба (`walk`, 1.2 с)** — подготовлен зацикленный клип на месте. Патруль/перемещение NPC не добавлены: торговец остаётся на своём месте.

Выдача семян, защита от повторной выдачи, контракты, сохранения, область взаимодействия, твёрдая коллизия и ящики рядом с торговцем сохранены. В каждом клипе есть каналы всех костей, чтобы предыдущие жесты не оставались при смене анимаций. Рюкзак следует груди; голова, волосы и борода — голове; полы плаща преимущественно тазу.

Повторная сборка (Blender Python `bpy`, проверено с 5.1.2):

```bash
python tools/rig_trader_model.py "торговец.glb" trader_build
godot --headless --path . -s tools/import_trader_model.gd -- trader_build
```

Готовые `.tres`/`.tscn` уже находятся в репозитории; Blender для игры не требуется. `test_trader_model.gd` проверяет веса, скелет, PBR, бюджет треугольников, клипы/переходы, положение стоп, открытие/закрытие контрактов и однократную выдачу семян.

## Баланс и прогрессия Главы 1

Сюжет: после урагана игрок восстанавливает разрушенную базу. Караванщик Степан дарит семена и приносит заказы соседей; деньги за заказы идут на ремонт дома и склада. Глава заканчивается экраном «База восстановлена» (8 вех, см. [Финал Главы 1](#финал-главы-1)), дальше — свободная игра.

**Принципы баланса.**
- Станки работают долго, но сами: запустил партию — ушёл рубить, копать, поливать. Игрок решает, что поставить в очередь, а не кликает на месте.
- Каждый промежуточный предмет куда-то нужен; у дорогих вещей несколько ветвей сырья (дерево, камень, жилы, ферма, металлолом).
- Из жил добывать выгоднее, чем перерабатывать хлам: руда с углём дают слиток дешевле металлолома, угольные брикеты — дешевле древесных.
- Путь до победы — ощутимый, но конечный. Тест `test_progression_balance.gd` раскладывает его на сырьё: ~145 единиц (дерево 56, камень 42, глина 24, вода 13, песок 3, руда 4, уголь 2, металлолом 1), ~20 мин работы станков, самый загруженный — верстак (~11 мин). С параллельной работой станков и сбором это около одного игрового дня (сутки — 24 мин). Леса (42 дерева) на путь хватает с запасом, но вырубленное нужно засаживать саженцами — см. [Деревья и посадка](#деревья-и-посадка).

**Ферма.** Время роста по культурам (`CROP_GROWTH_TIME`): морковь 120 с, картофель 150 с, пшеница 180 с (было 40 с для всех). Полного полива хватает примерно на 165 с, поэтому пшеницу за рост поливают дважды (или помогает дождь). Удобрение (×2) и Фермер (×1.35) ускоряют рост.

**Исправлено при разборе.** Энергосеть сканировала ветряк, батарею и фонари до того, как они попадали в группы, и показывала «Сеть +0.0 кВт»; теперь сеть пересканирует устройства, когда весь мир готов.

## Финал Главы 1

`scripts/core/victory_manager.gd` проверяет 8 вех дизайн-документа (прогресс в меню паузы). Для станков (дробилка, верстак, плавильня) недостаточно, чтобы они стояли на базе: каждый должен **завершить хотя бы один производственный цикл** (`completed_runs > 0`; циклы партий тоже считаются). ## Звук

Все звуки — бесплатные CC0-сэмплы (паки Kenney и OpenGameArt) плюс два сгенерированных; список источников — `assets/audio/CREDITS.md`. Звуки лежат в `assets/audio/*.tres` (текстовые `AudioStreamOggVorbis`, ~1,1 МБ). Пересборка: `tools/build_sounds.py` (обрезка, затухание, нормализация, моно OGG, бесшовные петли) → `tools/import_sounds.gd`.

## Сохранения

Реализация: `scripts/core/save_manager.gd` (формат, запись, загрузка) и `scripts/core/save_slots.gd` (слоты).

**Слоты.**

| Слот | Файл | Как пишется |
|---|---|---|
| 🔄 Автосохранение (`autosave`) | `user://savegame.json` | F5, сон в доме, автоматически каждые 5 минут игры (`AUTOSAVE_INTERVAL = 300` с) |
| 💾 Слоты 1–3 (`slot_1`…`slot_3`) | `user://saves/slot_N.json` | вручную из меню паузы |

Windows: `%APPDATA%\Godot\app_userdata\After The Storm\`. Автосохранение использует прежний файл, поэтому старые сохранения подхватываются без миграции. F9 загружает слот автосохранения. Неизвестные идентификаторы слотов отклоняются (`get_slot_path` → `""`).

**Формат v2** (`meta.format_version = 2`). Секции: `meta`, `player`, `inventory`, `day_night`, `weather` (включая `timer`, `cycle_index`), `buildings`, `energy`, `water`, `farmland`, `contracts`, `progress` (`victory_shown`), `cooking` (Глава 2: `{dishes: {item_id: {count, quality}}, mushrooms_collected, rebuilt_machines}` — приготовленные блюда с качеством, собранные грибы и восстановленные станки; секция необязательная, без неё прогресс главы обнуляется), `mushrooms` (лесные грибы: `{seed, mushrooms: [{has_mushroom, regrow_progress}]}` — раскладка и состояние каждого гриба). Станок без поля `rebuilt` считается готовым., `machines` (`completed_runs`, `pending_outputs`, `batch_total`, `batch_done`, `batch_to_buffer`, `level` — уровень станка, `wear` — состояние износа, `fuel_slots` и `fuel_burn_left` — топливо печи; все новые поля необязательные), `traders`, `resources` (состояние деревьев/камней, включая `is_growing` и `growth_hours` саженца), `dropped_items` (`[{item_id, amount, x, y, z}]`), `deposits` (`[{path, seed, size, voxels, discovered}]`: `voxels` — RLE-список `[материал, длина, …]`, при загрузке проверяются материалы и сумма длин), `farm_fields` (делянки, см. [Фермерство: делянки](#фермерство-делянки)), `fruit_trees` (сад: `[{type, pos, stage, growth, has_fruit, regrow, hits}]`, вид и стадия проверяются; в старых сохранениях секции нет — сад пуст), `berry_bushes` (`{seed, bushes: [{type, has_berries, regrow_progress}]}` — зерно раскладки ягодных кустов и урожай; в старых сохранениях секции нет — кусты остаются на новых местах), `seasons` (`{enabled, total_day, current_season, day_in_season, year, active_event, event_hours_left}` — календарь и активное погодное событие; секция необязательная, в старых сохранениях её нет, а календарь восстанавливается по игровому дню из `day_night`). В секции `buildings` дополнительно сохраняются `house_delivered` / `storage_delivered` (материалы, накопленные внутри здания для следующей стадии) и `house_delivered_credits` / `storage_delivered_credits`; в секции `machines` — `job_stash` (`{rebuild, repair, repair_q, upgrade}`: детали, накопленные внутри станка порционно) и `job_credits`. Все новые поля необязательные.

- Запись атомарная: сначала `*.tmp`, затем переименование.
- Перед изменением мира проверяются все секции; при ошибке загрузка отменяется.
- Файлы без `format_version` считаются v1 и мигрируют (`_migrate_save_data`); новые секции и поля необязательны.
- Поля партии без значений: работающий станок считается одиночным запуском (1 цикл, продукция в рюкзак).
- При загрузке все кучки на земле убираются и создаются заново из `dropped_items`.
- Файлы более новой версии формата отклоняются.
- `max_slots`/`max_weight` в файле справочные: при загрузке лимиты пересчитываются по рюкзаку и стадиям зданий.
- При изменении формата: увеличить `SAVE_FORMAT_VERSION`, добавить шаг в `_migrate_save_data`, обновить валидацию и этот раздел.
