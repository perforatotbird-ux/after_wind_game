## Обзор

Изометрический 3D-симулятор выживания: добыча ресурсов, переработка, фермерство, электрогенерация и восстановление разрушенного поселения после катаклизма. Текущее состояние — Глава 1 «Base Restored».

## Требования и запуск

- **Godot 4.7.2 stable** (целевая версия проекта).
- Python 3.9+ — только для тестового раннера.
- Blender не нужен: используются готовые GLB/TSCN, импорт `.blend` отключён (`filesystem/import/blender/enabled`).

```cmd
start.bat            :: игра
start.bat --editor   :: редактор Godot
start.bat --test     :: все тесты headless
```

## Управление

| Клавиша | Действие |
|---|---|
| W, A, S, D | Движение относительно ракурса камеры |
| Shift (удержание) | Спринт (тратит энергию; при перегрузе не ускоряет) |
| ЛКМ | Удар инструментом / взаимодействие с объектом в фокусе |
| ПКМ + мышь | Орбита камеры |
| Колесо мыши | Зум (3.5–26 м, шаг 1.5 м) |
| E | Действие: добыча, станки, урожай, NPC, забрать продукцию |
| 1–5 | Хотбар инструментов |
| I / Tab | Инвентарь и крафт |
| C | Выбор специализации (Шахтёр, Фермер, Учёный) |
| Y | Съесть еду |
| F5 / F9 | Быстрое сохранение / загрузка |
| ESC | Пауза, чек-лист финала, громкость |

## Выживание

- **Энергия** — тратится на спринт, добычу и движение с перегрузом; восстанавливается отдыхом и сном в доме (стадия 2+).
- **Жажда** — падает со временем; вода из резервуара, фильтрованная или бутилированная вода.
- **Голод** — падает медленнее; овощи, картофель, хлеб (`Y`).
- **Промокание** — под дождём; сушка под крышей дома или у плавильни.

## Инвентарь и грузоподъёмность

Реализация: `scripts/inventory/inventory.gd`.

**Слоты (жёсткий лимит).**
- Рюкзак задаёт число слотов `max_slots` (по умолчанию 12; берётся из `slots` лучшего рюкзака на поясе).
- Стакаемый предмет занимает `ceil(количество / max_stack)` слотов. `max_stack` берётся из ItemDB, иначе 99; при `stackable = false` — 1 (слот на штуку).
- Инструменты и снаряжение (категории `tool`, `equipment`) висят на поясе и слотов не занимают.
- Если слотов не хватает, предмет не подбирается: `add_item` возвращает `false`, испускается `item_rejected(item_id, amount, "no_slots")`.

**Вес (мягкий лимит).** `max_weight = base_max_weight (рюкзак) + бонусы зданий`.

| Состояние | Условие | Эффект |
|---|---|---|
| NORMAL | вес ≤ max_weight | нет штрафов |
| OVERLOADED | вес > max_weight | ходьба ×0.6, спринт не быстрее ходьбы, +2.5 энергии/с при движении |
| CRITICAL | вес ≥ max_weight × 1.25 | персонаж обездвижен (скорость 0) |

Смена состояния — сигнал `load_state_changed` и уведомление игроку. Штраф применяется к `walk_speed`/`sprint_speed` родителя-игрока и снимается при возврате в NORMAL.

**Бонусы зданий** (`repairable_building.gd`, `set_weight_bonus`):

| Стадия | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Склад, кг | 0 | +10 | +20 | +35 |
| Дом, кг | 0 | 0 | 0 | +15 |

## Производство и база

- **Дробилка** — камень в гравий/пыль, древесина в щепу.
- **Верстак** — компоненты (рукояти, болты, ткань), инструменты Lv.2.
- **Плавильня** — кирпич, стекло, железные слитки.
- **Фильтр воды**, **станция сбыта**, **доска контрактов** (караванщик Степан).
- **Грядки** — вскопка, посадка, полив (ведро/дождь), удобрение, урожай.
- **Энергосеть** — ветрогенератор, батарея, фонари ночью.
- **Здания** — дом и склад, по 4 визуальные стадии.

Станок считает завершённые циклы (`completed_runs`). Если готовая продукция не помещается в рюкзак, она остаётся в станке (`pending_outputs`) — подсказка «Забрать продукцию», забирается клавишей E.

## Финал Главы 1

`scripts/core/victory_manager.gd` проверяет 8 вех дизайн-документа (прогресс в меню паузы). Для станков (дробилка, верстак, плавильня) недостаточно, чтобы они стояли на базе: каждый должен **завершить хотя бы один производственный цикл** (`completed_runs > 0`). При выполнении всех вех показывается окно «BASE RESTORED»; факт показа сохраняется.

## Сохранения

Реализация: `scripts/core/save_manager.gd`. Файл: `user://savegame.json` (Windows: `%APPDATA%\Godot\app_userdata\After The Storm\savegame.json`). F5 — сохранение, F9 — загрузка, автосейв при сне.

**Формат v2** (`meta.format_version = 2`). Секции: `meta`, `player`, `inventory`, `day_night`, `weather` (включая `timer`, `cycle_index`), `buildings`, `energy`, `water`, `farmland`, `contracts`, `progress` (`victory_shown`), `machines` (`completed_runs`, `pending_outputs`), `traders`, `resources` (состояние деревьев/камней).

- Запись атомарная: сначала `*.tmp`, затем переименование.
- Перед изменением мира проверяются все секции; при ошибке загрузка отменяется.
- Файлы без `format_version` считаются v1 и мигрируют (`_migrate_save_data`); новые секции необязательны.
- Файлы более новой версии формата отклоняются.
- `max_slots`/`max_weight` в файле справочные: при загрузке лимиты пересчитываются по рюкзаку и стадиям зданий.
- При изменении формата: увеличить `SAVE_FORMAT_VERSION`, добавить шаг в `_migrate_save_data`, обновить валидацию и этот раздел.

## Тесты

```bash
python3 tools/run_tests.py --godot godot      # Linux / macOS
.\start.bat --test                            # Windows
python3 -m unittest discover -s tests -p 'test_*.py'   # самопроверка раннера
```

- Раннер автоматически находит все `tests/test_*.gd` (сейчас 23), запускает каждый отдельным процессом с таймаутом.
- Тест провален при ненулевом коде выхода или строке вывода, начинающейся с `ERROR`, `SCRIPT ERROR` или `FAIL:`.
- Логи и итоговый JSON: `outputs/test-results/`.
- `test_inventory_capacity.gd` покрывает слоты, стаки, перегруз, бонус склада и формат сохранения v2; `test_stage13_polish_and_finale.gd` — вехи финала, включая требование циклов станков.
- CI (GitHub Actions) пока не подключён.
