## Обзор

Изометрический 3D-симулятор выживания: добыча ресурсов, переработка, фермерство, электрогенерация и восстановление разрушенного поселения после катаклизма. Текущее состояние — Глава 1 «Base Restored».

## Требования и запуск

- **Godot 4.7.2 stable** (целевая версия проекта).
- Python 3.9+ — только для тестового раннера.
- Blender не нужен: используются готовые GLB/TSCN, импорт `.blend` отключён (`filesystem/import/blender/enabled`).

```cmd
start.bat            :: игра (открывается стартовое меню)
start.bat --editor   :: редактор Godot
start.bat --test     :: все тесты headless
```

## Управление

| Клавиша | Действие |
|---|---|
| W, A, S, D | Движение относительно ракурса камеры |
| Shift (удержание) | Спринт (тратит энергию; при перегрузе не ускоряет) |
| ЛКМ | Удар инструментом / взаимодействие с объектом в фокусе |
| ПКМ + мышь | Орбита камеры (чувствительность — в настройках) |
| Колесо мыши | Следующий / предыдущий инструмент пояса по кругу (рюкзак пропускается) |
| Ctrl + колесо | Зум камеры (3.5–26 м, шаг 1.5 м) |
| E | Действие: добыча, станки, урожай, NPC, подобрать предмет, забрать продукцию |
| 1–5 | Хотбар инструментов (5 — рюкзак, открывает инвентарь) |
| I / Tab | Окно рюкзака (клеточный инвентарь) |
| C | Выбор специализации (Шахтёр, Фермер, Учёный) |
| U / Y | Выпить воду / съесть еду |
| R / G / X (у делянки) | Сменить семена для посадки / зона работы 1×1 ↔ 3×3 / отменить неготовую делянку (дважды) |
| F5 / F9 | Быстрое сохранение / загрузка (слот автосохранения) |
| ESC | Меню паузы; в открытых окнах — закрыть окно |

Колесо не листает инструменты, пока открыто окно, игра на паузе или HUD блокирует ввод. Переназначение клавиш не поддерживается.

## Меню и настройки

Все окна собраны из общих стилей `scripts/ui/ui_style.gd` (те же цвета, рамки и кнопки, что у HUD).

**Масштаб и читаемость.** Интерфейс растягивается от базы 1600×900 (`project.godot`: `window/stretch/mode = canvas_items`, `aspect = expand`): на 1920×1080 он в 1.2 раза крупнее, на 1280×720 — в 0.8, раскладка везде одна. Поверх этого — настройка «Масштаб интерфейса» (75–150 %, `Window.content_scale_factor`).
- Окна HUD (заказы, ремонт, станция отправки, классы, пауза, финал) получают размеры из `hud.gd` (`WINDOW_SIZES`) и центрируются; если экран меньше, окно ужимается, а списки прокручиваются (`_layout_windows`, вызывается и при изменении размера окна).
- `UI.polish_text(окно)` вызывается после каждой перестройки содержимого: прокрутка только по вертикали, перенос строк у меток, «…» и подсказка у длинных названий в строках, шрифт не мельче 13 (кнопки — 14), оформление кнопок в стиле HUD.
- Требования заказов переносятся на новую строку (`HFlowContainer`), рецепты в окне станка — тоже.
- Хотбар, подсказка и уведомления подогнаны под ширину подписей (`_apply_hud_layout`).

**Стартовое меню** (`scripts/ui/main_menu.gd`). Открывается при запуске игры поверх живого мира: камера медленно облетает базу (оборот ≈ 2 мин), погода и сутки идут. Игрок, HUD и игровая камера на это время отключены.

| Пункт | Действие |
|---|---|
| ▶ Продолжить | Загрузить самое свежее корректное сохранение (по времени изменения файла). Неактивно, если сохранений нет; под кнопкой — слот, день, время и кредиты |
| ✦ Новая игра | Начать с чистого мира |
| 📂 Загрузить | Окно слотов (автосохранение + 3 ручных) |
| ⚙ Настройки | Окно настроек |
| ⏻ Выход | Закрыть игру |

Любой запуск партии перезагружает сцену мира: запрос передаётся через `GameSession` (meta у `SceneTree`) и разбирается в `world.gd` (`_init_session`), поэтому партия всегда стартует с чистого состояния. Меню показывается только если мир — текущая сцена и дисплей не headless (`@export enable_main_menu` позволяет выключить его); в тестах меню не появляется.

**Меню паузы** (ESC, `scripts/ui/pause_menu_controller.gd` поверх окна паузы HUD): продолжить, сохранить в слот, загрузить слот, настройки, громкость, чек-лист финала и «В главное меню».

**Окно слотов** (`scripts/ui/saves_panel.gd`): карточка на каждый слот — день, время, кредиты, дата записи; повреждённые файлы и файлы более новой версии помечаются ⚠️ и не загружаются. Перезапись и удаление слота требуют подтверждения (`scripts/ui/confirm_dialog.gd`). Сохранять в слот автосохранения вручную нельзя.

**Настройки** (`scripts/core/game_settings.gd`, окно `scripts/ui/settings_panel.gd`). Хранятся в `user://settings.cfg` (секция `[settings]`), применяются сразу и при каждом запуске. Значения из файла проверяются: вне диапазона — обрезаются, неверный тип — значение по умолчанию.

| Ключ | По умолчанию | Диапазон |
|---|---|---|
| `master_volume` | 1.0 | 0–1 |
| `sfx_volume` | 0.8 | 0–1 |
| `ambient_volume` | 0.6 | 0–1 |
| `fullscreen` | false | — |
| `resolution_index` | −1 (как в проекте) | −1…3: 1280×720, 1600×900, 1920×1080, 2560×1440 |
| `vsync` | true | — |
| `mouse_sensitivity` | 1.0 | 0.25–3.0 (множитель к 0.005) |
| `seconds_per_game_hour` | 60 (1 игровой час = 1 мин, сутки 24 мин) | 10–600 с; в окне — пресеты 20, 30, 45, 60, 90, 120, 180 с |
| `ui_scale` | 1.0 | 0.75–1.5; в окне — 75, 90, 100, 110, 125, 150 % |

Окно настроек разбито на разделы «Игра», «Звук», «Экран и интерфейс», «Камера» и прокручивается на маленьком экране. Длительность игрового часа применяется ко всем `DayNightCycle` (группа `day_night_cycle`, `set_seconds_per_game_hour`) сразу и при запуске. Она меняет смену дня и ночи и рост деревьев; станки, грядки, голод и жажда идут в реальном времени.

Кнопка «Сбросить» возвращает значения по умолчанию. Язык не настраивается (только русский).

## Время суток

`scripts/world/day_night_cycle.gd`. По умолчанию **1 игровой час = 1 минута** реального времени (сутки — 24 мин; раньше было 8 мин). Скорость настраивается (`seconds_per_game_hour`, см. [Меню и настройки](#меню-и-настройки)). Утро 5–11, день 11–17, вечер 17–21, ночь 21–5; сон в доме переносит на 6:00 следующего дня. `get_hours_per_second()` отдаёт текущую скорость другим системам (рост деревьев), `advance_hours()` продвигает время (переход отдыха).

**Отдых и сон** (`scripts/ui/rest_transition.gd`). Сон в отремонтированном доме (стадия 1+) запускает переход: затемнение и часы с бегущими стрелками (~2.4 с), игровое время идёт шагами синхронно с анимацией до 6:00 следующего дня; повторное нажатие заблокировано, движение и ввод выключены. Статы меняются в течение всего отдыха: энергия и здоровье к утру полностью, жажда и голод тратятся (после сна не ниже 35 %), мокрая одежда сохнет. После сна — автосохранение и итог «💤 Вы отдыхали N ч».

## Главный герой

Модель — шахтёр в каске с фонарём, рюкзаком и киркой (присланная AI-модель, ~1,5 млн треугольников без скелета). Сцена `scenes/player/miner_package_model.tscn` (в `player.tscn` масштаб 0.36, рост ~1,70 м).

- **Игровая версия**: тело `Miner_Body` ~14 тыс. треугольников + каска `Character_Helmet` (отдельный skinned меш, `set_hat_visible`), один атлас: цвет 2048, нормали 1024, ORM 1024 (G — шероховатость, B — металл), текстуры — `PortableCompressedTexture2D` (WebP) в `assets/models/character/hero/`. Детали high-poly перенесены запеканием (цвет и карта нормалей).
- **Скелет**: имена костей прежнего шахтёра (`Hip`, `Spine1/2`, `Neck`, `Head`, `Clavicle/Forearm/Arm/Hand`, пальцы, `Thigh/Calf/Foot/Toe`), веса — bone heat с правками по зонам: каска жёстко на голове, рюкзак — на корпусе, ноги ниже паха и перчатки не берут чужих костей. Пальцы перчаток-кулаков не деформируют меш (кости нужны для ретаргета и сокета).
- **Анимации**: все 22 клипа UAL1/UAL2 (`idle`, `walk`, `jog`, `run`, `mine`, `chop`, `dig`, `scoop`, `water`, `harvest`, `plant`, `eat`, `interact`, `pickup`, `carry_walk`, `talk`, `sit`, `hit`, `death`, `jump_*`) ретаргетятся на новый скелет `tools/retarget_ual_to_miner.gd` с прежними metadata (`play_speed`, `contact_time`, `ground_speed`).
- **Кирка**: отдельный меш `Pickaxe` (~1,5 тыс. треугольников, своя текстура 512) на `ToolSocket_R`. Сокет стоит в кулаке модели на оси черенка (+Y — к головке, +X — к костяшкам); черенок наклонён к костяшкам на 35° (`PICKAXE_GRIP_TILT_DEG`): в покое кирка горизонтально вперёд, как в исходной модели, в ударе головка уходит вперёд-вниз. Дыра в перчатке после выреза черенка закрыта.
- **Пересборка** (исходник 80 МБ и промежуточные файлы в репозиторий не входят):
  ```bash
  HERO_SRC=<исходный.glb> HERO_OUT=hero_build python3 tools/rig_hero_model.py --bake 2048   # Blender (bpy), ~5 мин
  godot --headless --path . -s tools/retarget_ual_to_miner.gd -- --hero hero_build --textures
  ```
- Тест: `tests/test_hero_model.gd` (размер меша, атлас, рост, стопы на земле, кирка через кулак).

## Деревья и посадка

Срубленное дерево **само не отрастает** — остаётся пень (`scripts/resources/resource_node.gd`, `requires_planting`; включается автоматически для узлов группы `trees`). Камни и металлолом восстанавливаются как раньше (`respawn_time`). Глину и песок добывают только в жилах — см. [Жилы и копание](#жилы-и-копание).

1. При полной вырубке выпадает древесина и **🌱 саженец** (`sapling`, `sapling_yield = 1`).
2. Подойдите к пню и нажмите E (топор не нужен): саженец списывается и сажается.
3. Саженец растёт `growth_hours = 8` игровых часов (8 мин при стандартной скорости). Модель плавно растёт от 18 % до 90 % размера, подсказка показывает процент и оставшиеся часы.
4. Выросшее дерево снова можно рубить.

В сохранении у ресурсного узла добавлены `is_growing` и `growth_hours` (необязательные; в старых сохранениях пни просто пустые).

## Ягодные кусты и сезоны

Два вида кустов из присланной модели (`berry_bush.glb`): синий куст — та же модель, перекрашены только ягоды. У каждого вида две модели — с ягодами и без (тот же куст без меша ягод).

| Куст | Ягода | За сбор | Отрастает | Сезон роста |
|---|---|---|---|---|
| 🍒 Куст красной ягоды (`scenes/resources/berry_bush_red.tscn`) | «Красная Ягода» (`red_berry`) | 3 | 36 игровых ч | весна, лето |
| 🫐 Куст синей ягоды (`scenes/resources/berry_bush_blue.tscn`) | «Синяя Ягода» (`blue_berry`) | 6 | 48 игровых ч | зима |

| Ягода | Сытость | Жажда | Сила (энергия) | Здоровье |
|---|---|---|---|---|
| Красная Ягода | +6 % | +8 % | +4 | не лечит (`health_bonus = 0`) |
| Синяя Ягода | +4 % | +3 % | +9 | не лечит |

- Подойдите к кусту и нажмите **E** — ягоды попадают в рюкзак (если хватает места), куст переключается на модель без ягод. Подсказка показывает, через сколько часов отрастут ягоды или что сейчас не сезон. Ягоды едятся как обычная еда (`Y` берёт их последними после хлеба и овощей).
- Скрипт — `scripts/resources/berry_bush.gd` (наследник `Interactable`, группа `berry_bushes`): `berry_item_id`, `berry_yield`, `grow_seasons`, `regrow_hours`, модели `FullModel`/`EmptyModel` (`scenes/resources/berry_bush/berry_bush_{red|blue}[_empty]_model.tscn`). Твёрдая коллизия `SolidBody`.
- **Сезоны — заглушка** `scripts/core/seasons.gd` (`const Seasons = preload(...)`): пока `Seasons.current_season == ""`, системы сезонов нет и ягоды отрастают круглый год. Будущей системе сезонов достаточно выставлять `Seasons.current_season` (`"spring"`, `"summer"`, `"autumn"`, `"winter"`): вне своего сезона часы роста у куста не идут.
- **Раскладка**: узел `BerryBushes` в `world.tscn` (`scripts/world/berry_bush_spawner.gd`) после генерации луга ставит по 2 куста каждого вида (`MAX_PER_TYPE = 2`) в случайных свободных местах кольца 9–32 м от центра базы: не во дворе, не на зданиях, станках, жилах, камнях, не у стволов и декоративных кустов, ≥ 5 м друг от друга. Зерно раскладки случайное в каждой новой игре и сохраняется.
- **Модель**: `tools/import_berry_bush.gd` (`godot --headless --path . -s tools/import_berry_bush.gd -- путь/berry_bush.glb`) → `assets/models/berry_bush/`: меши веток, трёх слоёв листвы и ягод (без UV, со сжатием атрибутов), материалы (листва двусторонняя; ягоды — `berry_bush_berry_red_material.tres` / `berry_bush_berry_blue_material.tres`).

## Фермерство: делянки

Делянка — фермерский участок любого прямоугольного размера от 1 до **128 клеток** (клетка 1 × 1 м), который игрок строит сам. Старые грядки базы (`farmland_plot.tscn`) остались как были.

**Как построить.**
1. Рюкзак (I / Tab) → кнопка **🌾 Делянка**. Рюкзак закрывается, включается размещение (`scripts/farming/farm_field_placer.gd`).
2. Наведите мышь на землю, **зажмите ЛКМ и тяните** — делянка растягивается по клеткам (больше 128 клеток не растянется), над ней размер и цена. Зелёная — место свободно, красная — занято: здания, станки, грядки, камни, стволы, жилы, вода, ягодные кусты, другая делянка или край карты. Отпустите ЛКМ — делянка размечена. ПКМ / Esc — отмена. Пока идёт размещение, удары и E выключены, ходить и крутить камеру можно.
3. На месте появляются колышки со шнуром, табличка и куча материалов. Подойдите и нажимайте **E** — из рюкзака забирается недостающее (можно приносить частями).
4. Когда всё принесено, стройка идёт **1 игровой день (24 ч)**: по мере прогресса появляются бортик и грядки. Пока делянка не готова, её можно отменить (**X** дважды) — материалы вернутся.

**Стоимость** (`FarmField.cost_for(w, h)`): древесина `4 + ⌈периметр / 2⌉` (бортик и колышки), камень `⌈клетки / 4⌉` (дренаж), опилки `⌈клетки / 4⌉` (мульча и компост). Например, 2×2 — 8 древесины, 1 камень, 1 опилки; 8×16 — 28 древесины, 32 камня, 32 опилок. Под делянкой убираются трава, цветы, мусор и декоративные кусты.

**Работа на делянке.** Подсвечивается клетка перед персонажем (или зона 3×3 — клавиша **G**). **E** выполняет нужное действие по порядку: убрать увядшее → собрать урожай → посадить → полить → удобрить; иначе подсказывает состояние. Каждая клетка засаживается своими семенами: **R** у делянки перебирает семена из рюкзака, в рюкзаке у семян есть кнопка «🌱 Сажать эти семена». Одна порция воды (`water` / `clean_water`) поливает клетку на +70 % или каждую клетку зоны 3×3 на +40 %. Одна порция удобрения — на 3 клетки. Дождь поливает все клетки.

**Культуры** (`scripts/farming/crop_db.gd`, время — в игровых часах):

| Культура | Рост | Норма влаги | Расход влаги | Вянет без воды | Урожай | Семена назад | Истощение почвы | Сезоны* |
|---|---|---|---|---|---|---|---|---|
| Морковь | 10 ч | 45–90 % | 5 %/ч | через 6 ч | 2–3 | 1–2 | 12 | весна–осень |
| Картофель | 16 ч | 30–70 % (переувлажнение — рост ×0.45) | 3.5 %/ч | через 9 ч | 2–4 | 1–2 | 20 | весна, лето |
| Пшеница | 22 ч | 20–80 % | 2.5 %/ч | через 14 ч | 3–5 | 1–3 | 8 | лето, осень |

\* Сезоны — заглушка `Seasons`: пока системы сезонов нет, всё растёт круглый год; когда `Seasons.current_season` задан, вне сезона культура не растёт.

**Механика роста** (по мотивам Stardew Valley, Farming Simulator и RimWorld):
- **Влага** 0–100 % у каждой клетки. В норме культура растёт с полной скоростью, суше нормы — ×0.4, переувлажнение — ×0.45…0.8 (у картофеля сильнее всех). Совсем сухая земля — рост стоит, копятся часы засухи; после предела культура **вянет** (E убирает). Пустая клетка сохнет на 1.5 %/ч. Цвет грядки показывает влагу: светлая — сухая, тёмная — мокрая.
- **Плодородие** 0–100 % (новая делянка — 60 %). Урожай истощает почву, удобрение даёт +35 % и ускоряет рост ×1.5 и +1 к урожаю, пустая клетка «под паром» восстанавливается на 0.5 %/ч. Почва ≥ 70 % — рост ×1.2, ниже 25 % — ×0.75 и −1 к урожаю.
- **Севооборот**: другая культура после прошлой на той же клетке — +1 к урожаю и вдвое меньше истощения; та же культура подряд истощает почву в 1.5 раза сильнее.
- **Качество** — доля часов роста в норме влаги: ≥ 60 % — «хороший» (+1), ≥ 85 % — «отличный» ★★ (+2).
- Фермер растит всё в 1.35 раза быстрее.

**Модель** (`scripts/farming/farm_field_meshes.gd`) собирается из частей, поэтому делянка любого размера выглядит одинаково аккуратно: приподнятые грядки с тремя бороздами, соломенная мульча-дорожка между ними, бортик из досок в два ряда с колышками через 2 м, табличка с размером, у стройки — колышки со шнуром и куча материалов. Культуры — по 4 стадии (посев, всходы, рост, зрелая) плюс увядшая; морковь — 2 ряда по 3 пучка с оранжевыми плечиками, картофель — 4 куста с цветами и клубнями, пшеница — 16 пучков колосьев. Грядки и растения — `MultiMesh`, поэтому даже 128 клеток почти ничего не стоят.

В сохранении — секция `farm_fields` (`[{x, z, w, h, state, delivered, build, cells: [[культура, рост, влага, плодородие, удобрено, увяло, засуха, уход, всего, прошлая культура], …]}]`).

## Выживание

- **Энергия** — тратится на спринт, добычу и движение с перегрузом; восстанавливается отдыхом и сном в доме (стадия 2+).
- **Жажда** — падает со временем; вода из резервуара, фильтрованная или бутилированная вода (`U`).
- **Голод** — падает медленнее; овощи, картофель, хлеб, ягоды (`Y`). Ягоды здоровье не лечат.
- **Промокание** — под дождём (быстрее в ливень); высыхает постепенно: на улице ~0.35 %/с (100 % сохнет ~5 игровых часов), в доме ~1.2 %/с, у плавильни ~6 %/с. Мокрая одежда замедляет и отнимает силы.
- **Истощение** — при нулевой энергии здоровье снижается (~0.5/с) с одноразовым предупреждением; при нуле также бьют жажда (1.2/с), голод (0.8/с) и бессонница 36+ ч (0.4/с). Здоровье восстанавливается само у сытого и напившегося персонажа и целиком за сон.

## Инвентарь и грузоподъёмность

Реализация: `scripts/inventory/inventory.gd` (модель), `scripts/ui/inventory_panel.gd` (окно), `scripts/ui/item_grid.gd` (сетка клеток), `scripts/ui/item_icons.gd` (иконки), `scripts/inventory/dropped_item.gd` (предметы на земле).

**Окно рюкзака** (I / Tab / слот 5). Пока окно открыто, персонаж не управляется (его обработка выключена); закрывается ESC, Tab или I.
- Сверху — шкала веса `текущий / допустимый кг` (цвет по состоянию нагрузки), занятые слоты, кредиты и инструменты пояса.
- Сетка 6 колонок, клеток столько, сколько `max_slots`. Каждая клетка — один стек: иконка ресурса и количество в углу (у стека больше 1 шт.); пустые клетки подписаны «Пустой слот».
- **Постоянные клетки** (`Inventory.slot_layout`, `get_slot_cells()`): у стека своё место. Добытое ложится в первую свободную клетку (или докладывается в свой стек), опустевшая клетка освобождается. Раскладка сохраняется в сейве (`inventory.slot_layout`, старые сейвы — раскладка по умолчанию).
- **Перетаскивание мышью**: стек в пустую клетку — перенос, на занятую — обмен (`move_slot`). Стек, брошенный за пределы окна, открывает «Выбросить…».
- **«⇅ Сортировать»** (`sort_slots`): по категории (ресурсы → материалы → продукция → компоненты → еда → семена), затем по названию; стеки одного предмета рядом.
- Двойной клик по еде / воде — съесть / выпить.
- Иконки рисуются кодом (`ItemIcons`, цвет и силуэт по категории/предмету) и кэшируются; у каждого предмета ItemDB есть иконка.
- Выбор клетки показывает карточку: название, описание, количество, вес штуки и вес всего стека. Для воды — кнопка «Выпить», для еды — «Съесть» (симулируют U / Y).
- **«🫳 Выбросить…»** или ПКМ по клетке открывает окно количества (`scripts/ui/quantity_dialog.gd`: ползунок + поле, кнопки «1», «½», «Всё»). Инструменты пояса выбросить нельзя.

**Предметы на земле** (`DroppedItem`). Выброшенное ложится перед персонажем кучкой с иконкой и подписью `×N`. Одинаковые предметы в радиусе 1.2 м складываются в одну кучку. E — подобрать: берётся сколько влезет в рюкзак, остаток остаётся лежать. Кучки сохраняются.

**Слоты (жёсткий лимит).**
- Рюкзак задаёт число слотов `max_slots` (по умолчанию 12; берётся из `slots` лучшего рюкзака на поясе).
- Стакаемый предмет занимает `ceil(количество / max_stack)` слотов. `max_stack` берётся из ItemDB, иначе 99; при `stackable = false` — 1 (слот на штуку).
- Раскладка по клеткам — `get_slot_stacks()`: полные стеки, затем остаток; сколько ещё влезет — `get_max_addable(item_id, amount)`.
- Инструменты и снаряжение (категории `tool`, `equipment`) висят на поясе и слотов не занимают.
- Если слотов не хватает, предмет не подбирается: `add_item` возвращает `false`, испускается `item_rejected(item_id, amount, "no_slots")`.

**Вес (мягкий лимит).** `max_weight = base_max_weight (рюкзак) + бонусы зданий`.

| Состояние | Условие | Эффект |
|---|---|---|
| NORMAL | вес ≤ max_weight | нет штрафов |
| OVERLOADED | вес > max_weight | ходьба ×0.6, спринт не быстрее ходьбы, +2.5 энергии/с при движении |
| CRITICAL | вес ≥ max_weight × 1.25 | персонаж обездвижен (скорость 0) |

Смена состояния — сигнал `load_state_changed` и уведомление игроку. Штраф применяется к `walk_speed`/`sprint_speed` родителя-игрока и снимается при возврате в NORMAL.

**Бонусы зданий** (`repairable_building.gd`, `set_weight_bonus`):

| Стадия | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Склад, кг | 0 | +10 | +20 | +35 |
| Дом, кг | 0 | 0 | 0 | +15 |

**Смена инструмента колесом** — `cycle_tool(direction)`: по кругу среди инструментов пояса, рюкзак пропускается.

## Производство и база

- **Дробилка** — камень в гравий/пыль, древесина в щепу. Модель — из Blender, с анимацией, см. [Модель дробилки](#модель-дробилки).
- **Верстак** — компоненты (рукояти, болты, ткань), инструменты Lv.2.
- **Плавильня** — кирпич, стекло, железные слитки (из металлолома или руды с углём). Модель — из Blender, см. [Модель плавильной печи](#модель-плавильной-печи).
- **Фильтр воды**, **станция сбыта**, **доска контрактов** (караванщик Степан).
- **Грядки** — вскопка, посадка, полив (ведро/дождь), удобрение, урожай.
- **Энергосеть** — ветрогенератор, батарея, фонари ночью.
- **Здания** — дом и склад, по 4 стадии. Склад — модель из Blender в трёх состояниях, см. [Модель склада](#модель-склада).

**Окно станка** (`scripts/ui/machine_panel.gd`, открывается по E у станка). Персонаж на это время не управляется; закрывается ESC или E.
- Основная область — **сетка рецептов** карточками одного размера (иконка продукции, название, вход → выход и время цикла; без сырья — серые, выбранный выделен). **Рюкзак игрока — справа**, нужное сырьё подсвечено. Внизу — состояние станка, топливо (у печи) и готовая продукция.
- **Сколько произвести** — поле с шагом, равным выходу одного цикла (принимаются только кратные значения, например 10 каменной пыли = 10 циклов дробления). Максимум — сколько позволяет сырьё в рюкзаке (не больше 99 циклов). Ниже — сколько сырья спишется и сколько займёт времени.
- **▶ Старт** — сырьё на всю партию сразу списывается из рюкзака (`start_batch`), циклы идут подряд. Видны прогресс цикла, номер цикла и оставшееся время.
- **⏹ Отменить** (с подтверждением) — партия останавливается, **сырьё не возвращается**, уже готовая продукция остаётся.
- Внизу — сетка рюкзака (ресурсы, нужные рецепту, подсвечены) и сетка выхода станка. Вся готовая продукция станка (как одиночные циклы `start_recipe`, так и партии `start_batch`) накапливается в собственном инвентаре станка (`pending_outputs`). При открытии станка [E] продукция остаётся в станке; игрок может забрать её целиком («📦 Забрать всё») или кликом по конкретной ячейке выхода (`collect_output_item`).

**Электропитание.** Станки — потребители энергосети (`power_draw`, кВт: дробилка 3.0, верстак 1.0, плавильня 5.0, фильтр 1.2): мощность списывается, только пока станок реально работает. Если батарея пуста, сеть обесточивает станки — цикл замирает на паузе (сырьё и прогресс партии не теряются), при восстановлении питания производство продолжается. Чтобы станки не «мигали» на пустой батарее, сеть возвращает питание при положительном балансе или заряде ≥ 15 %.

**Износ и ремонт** (`scripts/crafting/machine_wear.gd`, общий компонент). Станок изнашивается за каждый завершённый цикл (0.5 состояния из 100); ниже 50 % — «изношена», циклы ×1.25 дольше; при 0 — «неисправна»: новые запуски блокируются. Ремонт — кнопка в окне станка: 2 болта + 1 деревянная рукоять дают +50 % состояния; ресурсы списываются только при успешном ремонте, ремонт исправного отклоняется. Состояние видно в окне станка и сохраняется.

**Топливо печи.** У плавильни — 4 независимых топливных слота (до 9 штук в слоте): уголь горит 240 с, дрова 120 с, топливный брикет 360 с. Топливо кладётся из рюкзака (клик по пустому слоту или «⛽ Заправить»), клик по заполненному слоту забирает его назад. Печь расходует горение по времени; запуск партии требует запаса горения на все циклы (иначе отказ до списания сырья), а если топливо кончилось посреди партии — цикл встаёт на паузу до заправки. Топливо больше не является ингредиентом рецептов печи.

Станок считает завершённые циклы (`completed_runs`).

### Модель плавильной печи

Сцена `scenes/machines/smelter.tscn`, ресурсы `assets/models/smelter/`, референс `docs/art/smelter_reference.svg`, тест `tests/test_smelter_model.gd`.

- Шахтная печь «После бури»: цоколь из рваного камня, сужающийся кирпичный корпус с двумя железными обручами на заклёпках, арочная топка с приоткрытой дверцей (фасад — **+Z**), глиняный купол с трещинами и заплатой из профлиста, труба с колпаком. Сзади — мехи на столе с фурмой в стену и ящик угля, спереди слева — желоб слива и форма со слитками. Мехи и ящик стоят сзади, потому что слева и справа — дробилка и верстак.

Коллизии `SolidBody`: корпус 2.3 × 1.95 × 2.3, мехи и ящик.
- Текстуры хранятся как `PortableCompressedTexture2D` (WebP с потерями) внутри `.tres`, меши — со сжатыми атрибутами, все файлы текстовые и меньше 1 МиБ.

**Как пересобрать** (нужен Blender 5.x как модуль: `pip install bpy`):

Результат — `smelter_build/` (в `.gitignore`, с `.gdignore`). `--render 40` — дополнительно рендеры с трёх камер.
2. `godot --headless --path . -s tools/import_smelter_model.gd -- smelter_build/bake` — переводит `smelter_game.glb` и PNG в ресурсы `assets/models/smelter/*.tres` (касательные, сжатие, ORM).

### Модель дробилки

Сцена `scenes/machines/crusher.tscn`, ресурсы `assets/models/crusher/`, промт и референс — `docs/art/crusher_reference_prompt.md`, `docs/art/crusher_reference.svg` (рисует `tools/draw_crusher_reference.py`), анимация — `scripts/crafting/crusher_animator.gd`, тест — `tests/test_crusher_model.gd`.

Разгон — 1.4 с; после остановки маховики крутятся по инерции ещё ~3 с, лампа гаснет сразу. Корпус почти не трясётся: `shake_strength = 0.25` у `ProductionMachine` (у других станков — 1.0).

**Как пересобрать** (нужен Blender 5.x как модуль: `pip install bpy`):
1. `python3 tools/create_crusher_model.py --bake 2048` — строит модель, применяет модификаторы, склеивает детали по группам (корпус и подвижные части), делает общую развёртку всех групп и запекает в Cycles цвет, нормали (со скруглёнными рёбрами из Bevel-узла), AO, шероховатость и металл (~10 мин на 2 ядрах). | 1 Расчищенный навес | амбар | каркас на каменных опорах с полом, подкосами, стропилами и припасами внутри; поверх стропил натянут зелёный тент на растяжках | `Frame` + `Tarp` |
| 2 Крытый амбар | амбар | тот же каркас + дощатые стены с окнами, ворота с Z-обвязкой (левая створка приоткрыта), кровля из профлиста, вывеска «СКЛАД», бочка для дождевой воды | `Frame` + `Shell` |
| 3 Логистический комплекс | комплекс | кирпичный цоколь и пилястры, красная обшивка внахлёст, оцинкованная кровля со световыми листами, водостоки, рулонные ворота, стеллаж с грузом внутри, вывеска «СКЛАД №1»; справа — сортировочный навес с ящиками для камня, металла и дров и поворотная укосина с ручной лебёдкой на шестернях | `Model` + `Yard` + подъёмник |

- Фасад — **+Z** (во двор). Габарит основного объёма 4.8 × 3.9 м, с навесом и краном — до 6.6 м по X; высота: руины ≈ 2.7 м, амбар ≈ 3.8 м, комплекс ≈ 4.5 м. Треугольников: ≈ 13 тыс. / 24 тыс. / 37 тыс.
- У каждого состояния свой атлас: цвет 2048, нормали 1024, ORM 1024 (R — AO, G — шероховатость, B — металл). Текстуры — `PortableCompressedTexture2D` (WebP) внутри `.tres`, меши со сжатыми атрибутами, каждый файл меньше 1 МиБ (поэтому комплекс разбит на `Model` — здание и `Yard` — интерьер, навес и кран).
- **Подъёмник** (`Visuals/Stage3/HoistAnimator`, работает, пока стадия видна): цикл 12 с — ящик стоит на поддоне, рукоять крутит малую шестерню, большая шестерня с барабаном поворачивается на «подъём / радиус барабана» (передаточное число 2.83, рукоять — навстречу), цепь укорачивается, ящик поднимается на 0.45 м, висит, покачиваясь на цепи (маятник), и опускается обратно. Подвижные меши `Gear`, `Crank`, `Chain`, `Hook` — с центром на своей оси/точке подвеса.
- Коллизии: общий `StaticBody3D/SolidShape` и `Stage3Sorting` (навес и кран) — его `repairable_building.gd` включает только на стадии 3 (общее правило: форма `StaticBody3D/Stage<N>…` активна только на стадии N).

**Как пересобрать** (нужен Blender 5.x как модуль: `pip install bpy`):
1. `STORAGE_STATE=ruins python3 tools/create_storage_model.py --bake 2048` — и так же для `barn` и `complex`: строит состояние, применяет модификаторы, склеивает детали по частям, делает общую развёртку и запекает в Cycles цвет, нормали, AO, шероховатость и металл (~8 мин на состояние). Результат — `storage_build/bake_<состояние>/` (в `.gitignore`). `STORAGE_STATE=all … --render 32` — все три рядом для рендера.
2. `godot --headless --path . -s tools/import_storage_model.gd -- storage_build [состояния…]` — переводит glb и PNG в `assets/models/storage/*.tres` и печатает оси подвижных частей (они же стоят в сцене).

## Жилы и копание

Реализация: `scripts/world/voxel_deposit.gd` (жила), `scripts/world/voxel_textures.gd` (текстуры), `scripts/world/ground_terrain.gd` (вырез в земле), шаг на уступ — `player.gd` (`_try_step_up`).

**Как играется.** Жила — участок земли 8×8 м из разрушаемых блоков 0.5 м глубиной 4 м (16×16×8 блоков). Сверху это обычная трава; выдают её только камешки-«выходы» породы (рыжие — руда, чёрные — уголь, светлые — песок/глина). Наведите курсор на блок рядом с персонажем (досягаемость 2.4 м от груди; без мыши — блок перед персонажем: стенка, затем грунт перед ногами, затем под ногами) и бейте ЛКМ или E. Блок под прицелом подсвечивается: зелёный — можно копать, красный — нужен другой инструмент или блок не копается.

| Блок | Инструмент | Ударов (Lv.1) | Добыча | Энергия за удар |
|---|---|---|---|---|
| Грунт | лопата (кирка +1 удар) | 1 | ничего; 12% — камень | 1.2 |
| Песок | лопата (кирка +1 удар) | 1 | песок ×2 | 1.4 |
| Глина | лопата (кирка +1 удар) | 2 | глина ×2 | 1.8 |
| Уголь | только кирка | 3 | уголь ×2 | 2.4 |
| Железная руда | только кирка | 4 | руда ×1–2 | 3.0 |
| Скальное основание, внешние стенки | — | не копаются | — | — |

- Инструмент Lv.2: двойной удар, −35% энергии, +1 к добыче ресурса. Шахтёр: +1 угля/руды и −20% энергии на них.
- Ресурсы лежат пятнами по глубине (слой 0 — трава): песок 1–3, глина 1–5, уголь 2–6, руда 3–6; нижний слой — скальное основание. В жиле 1–3 вида ресурсов (`resource_types` или случайно по `deposit_seed`). Первый выкопанный блок ресурса — сообщение «Найдена жила», найденное видно в подсказке.
- Если рюкзак полон, добыча падает кучкой у блока.
- Выбраться из ямы: персонаж сам шагает на уступ в 1 блок (`STEP_HEIGHT = 0.55`, только тела группы `voxel_terrain`), уступ в 2 блока — уже стена. Копайте ступенями.
- Жилы не восстанавливаются: выкопанное остаётся ямой (и в сохранении).
- На карте 3 жилы (`Deposits` в `world.tscn`): «Ближняя» (8, 15) — песок и глина, «Восточная» (18, −6) — уголь и руда, «Западная» (−18, −2) — случайный набор (сид 37).

**Новые предметы и рецепты.** `coal` (уголь), `iron_ore` (железная руда). Плавильня: `smelt_iron_ore` — 2 руды → 1 железный слиток (уголь кладётся в топливный слот печи). Верстак: `press_coal_briquette` — 2 угля + 1 опилки → 3 топливных брикета; уголь также идёт в аккумуляторный элемент. Время циклов — в разделе [Баланс](#баланс-и-прогрессия-главы-1).

**Техника.**
- Воксели — `PackedByteArray` (`x + z·N + y·N²`), материалы `Mat`: AIR, SOIL, SAND, CLAY, COAL, IRON_ORE, BEDROCK. После каждого разрушенного блока меш (только открытые грани, атлас UV, затемнение по глубине) и `ConcavePolygonShape3D` пересобираются целиком — для 2048 блоков это миллисекунды.
- Персонаж каждый кадр вызывает у жилы `update_aim(player)`; расстояние, поворот и проверка удара берут `get_interaction_point()` / `is_in_reach()` (общие методы для объектов с прицелом). Свойства `required_tool` и `current_hits` относятся к блоку под прицелом, поэтому замах и hit-stop работают как у камней.
- Текстуры — процедурные пиксельные тайлы 32×32 (трава, дёрн сбоку, грунт, песок, глина, уголь, руда, скальное основание) в атласе с рамкой 8 px против смешивания mipmap-ов. Земля мира — гладкий моховой шейдер без пикселей, см. [Луг и декор](#луг-и-декор). Превью: `godot --headless --path . -s tools/export_voxel_textures.gd -- out.png`.
- `ground_terrain.gd` заменяет ящик земли 80×80 полосами вокруг участков жил (`get_footprint_rect`); на участке землю держит и рисует сама жила.
- Новая жила: узел `Area3D` со скриптом `voxel_deposit.gd` в `Deposits`, верх участка на y = 0, без поворота, на свободном месте (камни и постройки внутри участка будут висеть над ямой).

## Луг и декор

Реализация: `scripts/world/meadow_ground.gd` (шейдер земли), `scripts/world/meadow_grass.gd` (меши и шейдеры травы), `scripts/world/meadow_decor.gd` (узел `Meadow` в `world.tscn`). Тесты — `tests/test_meadow_and_debris.gd`, `tests/test_stylized_grass.gd`.

- **Глина и песок больше не лежат шарами на карте** — узлы `Clay1/2`, `Sand1/2` и плоский квадрат двора `DirtYard` удалены. Глину и песок дают только жилы: в «Ближней» и «Западной» вместе ≈ 100 блоков песка и ≈ 90 блоков глины, по 2 единицы с блока — с большим запасом на всю Главу 1 (нужно ~24 глины и ~3 песка). Сцены `clay_node.tscn`/`sand_node.tscn` остались в проекте, но не используются.
- **Земля** (`MeadowGround.get_material(yard_rect)`, `ShaderMaterial`): гладкий тёмно-зелёный «мох» (смесь двух оттенков по fbm-шуму) под травой, сочные и выгоревшие пятна, редкие проплешины голой земли с крапинками. Вокруг базы — вытоптанный двор с неровным краем (`yard_rect` у `Ground`, по умолчанию `Rect2(-11, -9, 22, 16)`; `yard_signed_distance` < 0 — внутри).
- **Декор** генерируется при старте детерминированно (`decor_seed = 4242`, у каждого слоя своё зерно, ~400 мс):

| Слой | Сколько | Как сделано |
|---|---|---|
| Пучки травы | ≈ 40 000 (~7 на м²) | стилизованные пучки `MeadowGrass`, `MultiMesh` по чанкам 12 м × вид × вариант; вблизи (до 36 м) — полные пучки, дальше — простой дальний пучок на каждый третий |
| Клевер | ≈ 5 800 | трилистники пятнами у корней травы |
| Цветы | 900 | группами, 5 цветов (белые, жёлтые, синие, фиолетовые, розовые) |
| Кусты | 46 | `StaticBody3D` группы `bushes` с коллизией-цилиндром; 6 вариантов (с ягодами и цветами), чаще на опушках |
| Камешки, ветки, листья, грибы | 380 / 170 / 650 / 70 | листья и грибы — под деревьями |
| Обломки после бури | доски 50, кирпичи 45, листы металла 22 | в основном вокруг двора |

- **Стилизованная трава** (`meadow_grass.gd`) — как на референсе: толстые изогнутые листья со скруглёнными кончиками, тёмные у корня и жёлто-зелёные на концах.
  - Виды пучков: `LUSH` (сочный, 3 варианта), `LUSH_WIDE` (широкие листья), `TALL` (дикие высокие куртины по шуму), `SHORT` (примятая у края двора), `FAR` (дальний план), `CLOVER`. Пучок — 70–100 треугольников, меши кэшируются.
  - Шейдер: двусторонние листья, мягкий свет (`lambert_wrap`), просвечивание (`BACKLIGHT`), затенение у корня, ветер с порывами, нормали частично смотрят вверх — луг не «рябит». Цвет пучка подкрашивается по шуму: сочные и выгоревшие (желтоватые) пятна.
  - Трава растёт и на жилах; когда блок верхнего слоя выкопан, пучки над ним прячутся (жила шлёт сигнал `terrain_rebuilt`, луг вызывает `sync_with_deposits()`, счётчик `counts["grass_hidden"]`). Работает и после загрузки сохранения.
- Декор не залезает на станки, здания, грядки, декоративные скалы, ресурсы и жилы: строится маска 0.25 м (`get_mask_at`) по их мешам (`node_footprint`, без высоких деталей вроде лопастей ветряка) и стволам деревьев. Трава и мусор — без коллизии и без теней (кроме кустов).
- Чтобы поменять плотность — экспорты `grass_step` (шаг сетки травы, 0.36 м), `grass_lod_distance` (36 м), `flower_count`, `bush_count` и др. у узла `Meadow`; `generate()` пересобирает всё.

## Баланс и прогрессия Главы 1

Сюжет: после урагана игрок восстанавливает разрушенную базу. Караванщик Степан дарит семена и приносит заказы соседей; деньги за заказы идут на ремонт дома и склада. Глава заканчивается экраном «База восстановлена» (8 вех, см. [Финал Главы 1](#финал-главы-1)), дальше — свободная игра.

**Принципы баланса.**
- Станки работают долго, но сами: запустил партию — ушёл рубить, копать, поливать. Игрок решает, что поставить в очередь, а не кликает на месте.
- Каждый промежуточный предмет куда-то нужен; у дорогих вещей несколько ветвей сырья (дерево, камень, жилы, ферма, металлолом).
- Из жил добывать выгоднее, чем перерабатывать хлам: руда с углём дают слиток дешевле металлолома, угольные брикеты — дешевле древесных.
- Путь до победы — ощутимый, но конечный. Тест `test_progression_balance.gd` раскладывает его на сырьё: ~145 единиц (дерево 56, камень 42, глина 24, вода 13, песок 3, руда 4, уголь 2, металлолом 1), ~20 мин работы станков, самый загруженный — верстак (~11 мин). С параллельной работой станков и сбором это около одного игрового дня (сутки — 24 мин). Леса (42 дерева) на путь хватает с запасом, но вырубленное нужно засаживать саженцами — см. ## Финал Главы 1

`scripts/core/victory_manager.gd` проверяет 8 вех дизайн-документа (прогресс в меню паузы). Для станков (дробилка, верстак, плавильня) недостаточно, чтобы они стояли на базе: каждый должен **завершить хотя бы один производственный цикл** (`completed_runs > 0`; циклы партий тоже считаются). При выполнении всех вех показывается окно «BASE RESTORED»; факт показа сохраняется.

## Звук

Все звуки — бесплатные CC0-сэмплы (паки Kenney и OpenGameArt) плюс два сгенерированных; список источников — `assets/audio/CREDITS.md`. Звуки лежат в `assets/audio/*.tres` (текстовые `AudioStreamOggVorbis`, ~1,1 МБ). Пересборка: `tools/build_sounds.py` (обрезка, затухание, нормализация, моно OGG, бесшовные петли) → `tools/import_sounds.gd`.

`AudioManager` (`scripts/audio/audio_manager.gd`) хранит таблицу `SOUNDS`: имя → варианты. При `AudioManager.play("имя")` выбирается случайный вариант (не тот же, что в прошлый раз) и чуть меняется высота — удары и шаги не звучат одинаково. Интерфейс и музыка играют без разброса.

| Звук | Когда |
|---|---|
| `hit_wood`, `hit_stone`, `hit_metal` | удар топором по дереву, киркой по камню и жилам, по металлолому |
| `dig` (`till_soil`) | лопата: копание земли, вскапывание грядки |
| `swing` | замах инструментом (генерируется) |
| `footstep_grass`, `footstep_dirt` | шаги каждые ~1,6 м: по земле — трава, по камню и постройкам — грунт; на бегу громче |
| `pickup`, `drop` | подбор и выброс предмета |
| `berry_pick`, `plant`, `harvest` | сбор ягод, посадка семян/саженца, урожай |
| `water_splash`, `water_fill`, `drink`, `eat` | полив, набор воды в ведро, питьё, еда (генерируется) |
| `machine_start`, `machine_done`, `build` | запуск и готовность станка, разметка и стройка делянки |
| `coins`, `victory_fanfare` | оплата заказа, финал главы |
| `ui_click`, `ui_open`, `ui_close`, `ui_error` | кнопки, открытие/закрытие рюкзака и окна станка, ошибка размещения |

Фон: петли ветра (всегда), птиц (когда нет дождя) и дождя (`set_weather_rain()` из `world.gd`). Смена погоды — плавный переход за 2,5 с. Громкость эффектов и фона — в настройках.

## Сохранения

Реализация: `scripts/core/save_manager.gd` (формат, запись, загрузка) и `scripts/core/save_slots.gd` (слоты).

**Слоты.**

| Слот | Файл | Как пишется |
|---|---|---|
| 🔄 Автосохранение (`autosave`) | `user://savegame.json` | F5, сон в доме, автоматически каждые 5 минут игры (`AUTOSAVE_INTERVAL = 300` с) |
| 💾 Слоты 1–3 (`slot_1`…`slot_3`) | `user://saves/slot_N.json` | вручную из меню паузы |

Windows: `%APPDATA%\Godot\app_userdata\After The Storm\`. Автосохранение использует прежний файл, поэтому старые сохранения подхватываются без миграции. F9 загружает слот автосохранения. Неизвестные идентификаторы слотов отклоняются (`get_slot_path` → `""`).

**Формат v2** (`meta.format_version = 2`). Секции: `meta`, `player`, `inventory`, `day_night`, `weather` (включая `timer`, `cycle_index`), `buildings`, `energy`, `water`, `farmland`, `contracts`, `progress` (`victory_shown`), `machines` (`completed_runs`, `pending_outputs`, `batch_total`, `batch_done`, `batch_to_buffer`, `wear` — состояние износа, `fuel_slots` и `fuel_burn_left` — топливо печи; все новые поля необязательные), `traders`, `resources` (состояние деревьев/камней, включая `is_growing` и `growth_hours` саженца), `dropped_items` (`[{item_id, amount, x, y, z}]`), `deposits` (`[{path, seed, size, voxels, discovered}]`: `voxels` — RLE-список `[материал, длина, …]`, при загрузке проверяются материалы и сумма длин), `farm_fields` (делянки, см. [Фермерство: делянки](#фермерство-делянки)), `berry_bushes` (`{seed, bushes: [{type, has_berries, regrow_progress}]}` — зерно раскладки ягодных кустов и урожай; в старых сохранениях секции нет — кусты остаются на новых местах).

- Запись атомарная: сначала `*.tmp`, затем переименование.
- Перед изменением мира проверяются все секции; при ошибке загрузка отменяется.
- Файлы без `format_version` считаются v1 и мигрируют (`_migrate_save_data`); новые секции и поля необязательны.
- Поля партии без значений: работающий станок считается одиночным запуском (1 цикл, продукция в рюкзак).
- При загрузке все кучки на земле убираются и создаются заново из `dropped_items`.
- Файлы более новой версии формата отклоняются.
- `max_slots`/`max_weight` в файле справочные: при загрузке лимиты пересчитываются по рюкзаку и стадиям зданий.
- При изменении формата: увеличить `SAVE_FORMAT_VERSION`, добавить шаг в `_migrate_save_data`, обновить валидацию и этот раздел.
