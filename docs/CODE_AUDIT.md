# Аудит качества кода

Проверенная база: `main`, commit `fa064486e5f6bc2f1a75d00992bbae9f9bcc2534`.
Среда: Linux x86_64, Godot 4.7.2 stable (`ed1daf0bf`), Python 3.13.

## Объём проверки

Проверены чистый импорт проекта, существующие интеграционные тесты и ключевые
пути сохранений, инвентаря, крафта, экономики и прогресса. Это не исчерпывающий
аудит каждого ассета и Blender-инструмента. Главная цель исправлений —
воспроизводимые функциональные дефекты, а не массовое изменение стиля.

- До исправления импорта чистый клон не загружал текстуру и сцену героя.
- После исправления импорта все исходные **21/21 GDScript-тест** прошли без
  `ERROR` / `SCRIPT ERROR` на Godot 4.7.2.
- Новый `test_code_quality.gd` до исправлений выявил **7 неуспешных проверок**
  и два GDScript runtime error; после исправлений проходит.
- Итоговая проверка на чистом импорте: **22/22 GDScript-теста**.
- Проверка самого запуска: **5/5 Python-тестов** (успех, nonzero exit, ошибка
  движка при exit 0, таймаут, отсутствующий executable).
- Дополнительно: синтаксическая проверка **28/28 игровых GDScript-скриптов**
  через `--check-only` с путями `res://`, компиляция Python-инструментов,
  `git diff --check` и headless-запуск главной сцены на 180 кадров без ошибок.

Команды воспроизведения:


Логи: `outputs/test-results/`; итоговый JSON: `outputs/test-results/results.json`.

## Оставшиеся риски и следующие шаги

1. **Сохранение мира ещё не полное.** Истощение/таймер восстановления ресурсных
   узлов, таймер/индекс погодного цикла и состояние показанного финала не входят
   в формат. Для них нужны отдельные round-trip тесты. В README убрано обещание
   «полной сериализации».
2. **Грузоподъёмность складывается непоследовательно.** Ремонт склада увеличивает
   `max_weight`, а `Inventory.upgrade_tool("large_backpack")` присваивает 75 кг,
   стирая прибавку от зданий. Исправление требует определить правило сложения
   перков и миграцию сохранённых значений; в этом патче баланс не менялся.
3. **Критерии победы слишком поверхностны.** Дробилка/верстак/печь считаются
   готовыми по наличию узла в сцене, а не по реальному использованию или ремонту;
   подписи говорят о 2/2, хотя здания имеют 3 стадии. Нужна согласованная модель
   прогресса, иначе изменение логики незаметно поменяет условия победы.
4. **Ограничения проверки.** Не проверены вручную графика/звук, экспорт сборки,
   Windows-лаунчер и файловые сбои Windows. Headless-тесты не гарантируют
   визуального качества. Совместимость с Godot 4.3 не заявляется.
5. **Валидация — не миграция схемы.** Нужны явные правила будущих версий и
   проверки согласованности диапазонов с ёмкостями конкретных узлов. Добавленная
   проверка типов устраняет воспроизведённое частичное применение некорректного
   JSON, но не заменяет транзакционную загрузку произвольного будущего формата.
